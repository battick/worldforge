# WorldForge · 个人世界观知识库

一个**单机优先**的个人世界观管理工具。两条主线：

> **① 新建世界：你随手投喂材料 → AI 读懂、提问、统筹 → 你确认，世界才诞生**
>
> **② 日常协作：AI 产出候选 → 你审查拍板 → 写入正式设定库**

AI 永远不会直接改你的设定集。所有生成内容先落到「审查队列」，采纳才入库，驳回即丢弃，也可以先改再采纳。

---

## 新建世界是怎么走完的

产品里没有「填表创建世界」这一步，也没有预置的示例世界。第一个世界由你和 AI 一起长出来：

1. **随手放素材** —— 旧文章、设定稿、大纲、笔记、图片（png/jpg/webp），
   或者现场写几条规则（例如「力量必须有代价」）。文件在本地解析，图片会压缩后交给模型读。
2. **AI 读完之后来问你** —— 它先讲清「我读懂了什么、这些结论来自哪份材料」，
   再问几个真正影响世界走向的问题，每个都附上它的建议答案；
   不想动脑就点「你来定」，它会自己拍板。信息够了它会主动收口，最多追问 3 轮。
3. **统筹成一份设定草案** —— 世界名、一句话定位、题材、创作纪律、底层规则、
   分类、首批条目（含正文）、关系连线，一次给全。
4. **你确认，它才真的存在** —— 草案上的每条都能改、能删、能取消勾选，
   还能丢一句「势力太少了，再加两个互相制衡的」让 AI 重写一版（可反复）。
   点下确认时会再问一次，把 AI 替你做过主的地方列出来。
   **在这之前，数据库里不会有任何世界数据。**

你投喂的那批素材也会一并进入新世界的「资料库」，方便回溯每条设定的来源。

## 怎么运行

### 方式一：双击启动（推荐）

双击 **`start.bat`**。首次运行会自动装依赖并构建，之后每次秒开，浏览器会自动打开。

> 需要先装 [Node.js](https://nodejs.org) 18 或更高版本。

### 方式二：命令行

```bash
npm install          # 首次
npm run build        # 首次（或代码有改动时）
npm start            # 启动，默认 http://127.0.0.1:5188
```

换端口：`node server.mjs --port 5189`

### 关于端口被占用

启动器自己会处理，不需要你手动干预：

- **如果应用本来就在跑**（你上次没关窗口）：不会重复启动，而是直接把浏览器打开到已有那个地址。这一点很重要——数据是按地址隔离的，另起一个端口会让你以为数据丢了。
- **如果端口被别的程序占用**：自动往后找可用端口（5188 → 5189 → …），并在控制台告诉你实际地址。

### 方式三：开发模式

```bash
npm run dev          # http://127.0.0.1:5180，改代码自动热更新
```

> ⚠️ **不要直接双击 `dist/index.html`**。生产包是 ES Module，用 `file://` 打开会被浏览器的跨域策略拦死，页面会白屏。必须通过上面的本地服务访问。

## 接入 AI

打开左侧「设置 → AI 模型」，填入自己的 API Key。已内置这些厂商预设（都走 OpenAI 兼容协议，按「常用 / 聚合与海外 / 本机」分了三组）：

- **常用**：DeepSeek、通义千问、智谱 GLM、Moonshot 月之暗面、火山方舟（豆包）、腾讯混元、百度千帆、阶跃星辰、零一万物
- **聚合与海外**：OpenAI、OpenRouter、SiliconFlow、Google Gemini、xAI、Groq、Mistral、302.AI
- **本机**：Ollama、LM Studio、自定义 / 中转站

填完点「测试连接」确认可用。**API Key 只存在你自己浏览器的本地存储里**，不会上传到任何地方（除了直接发给模型厂商本身）。

### 型号：不只有写死的那几个

内置的那几个型号只是**兜底**（还没取过列表时给你几个能用的名字）。型号换得比代码快，写死在仓库里必然过时 —— 所以点型号旁边的「选型号」，它会去厂商的 `GET {baseUrl}/models` 拉一份**你这把钥匙真正能用**的清单。

- 面板打开时自动拉一次，拉到就缓存在本机（重开不再重复请求），只有点「重新获取」才会再拉；
- 可以搜索；厂商返回的清单按「能对话的在前」排，向量 / 语音这类**标一句「可能不是对话模型」挪到后面**，而不是藏起来；
- 「最近用过」和「内置候选」各占一组，同一个型号只出现一次；
- 拉失败时把厂商的原话摆出来（状态码 + 原因），**而且不会把上一份好清单扔掉**；
- **型号永远可以手填**：自建网关的私有型号、私有部署、厂商还没列出来的新模型，直接敲进输入框就行。

### 清单上有，不等于用得了：自动探测可用性

`GET /models` 只说明**账面上**有这些型号，不说明能不能真的跑通 —— 中转站尤其如此：清单里躺着几十个型号，其中一部分一用就回 `402 Sorry, your account balance is insufficient.`，而人往往是在**已经坐下来开始写**之后才发现。

所以清单一到手，就会**自动逐个探一遍**（一个 `max_tokens: 1` 的极短请求），结论画在每一项左边那条小竖条上：

- **绿** = 它真的回话了（**只有真的拿到回复才算可用** —— 2xx 但内容为空不算）；
- **橙** = 渠道报余额 / 额度不足（单独一档：它「不是这个型号的错」，要做的事也不一样 —— 去充钱，而不是换型号）；
- **红** = 这个型号有问题（不存在 / 钥匙不对 / 被限流 / 通了但读不懂）；
- **灰** = 还没探过（**「没探完」不等于「不可用」**，所以不写结论）。

鼠标停在那条竖条上会说明原因，并把**厂商原话**带上（那是排查的唯一线索）。

几条纪律：**向量 / 语音那类根本不探**（它们本来就回不了对话，探了必然一片红，看着像渠道坏了）；**结论缓存 24 小时**且跟着 API Key 走（换了钥匙就是换了账户，旧结论不能当新结论用）；**连着几个都连不上就收手**（剩下几十个只会白打一遍，还看不出新东西），并提示你去查地址和网络；跑的过程中随时可以**停止**。选中某个型号时，如果它还没结论，也会单独探它一次。

**一次探几个是自己定的**（选型号面板里那一行的「探测上限」，默认 40）：每一次探测都是**一条真实的请求**，所以这个数就是你要发给厂商的请求数 —— 聚合站的清单动辄一两百条，全打一遍对厂商是骚扰、对中转站更容易直接吃限流，而被限流耽误的是你真正想干的活。默认保守、上限交给你定：

- 填**任意条数**（比如 100）——适合「这一份清单我基本都会用到」；
- 勾**不限制** —— 整份清单一次探完。没探到的那些不会被丢掉：界面如实报成「还有 N 个没探（一次最多探 40 个）」，点「重新探测」接着来；把上限调大之后，再打开面板也会自动把剩下的补上。

这个设置**只有选型号面板里那一个入口**（就摆在探测那一行，改完点「重新探测」即生效）。设置页只留接入信息（服务商 / 地址 / 钥匙 / 型号），不再摆一份同样的控件 —— 同一个设置开两个门，只会让人怀疑它们是不是同一个。

切服务商时**每家各记一个型号**，切走再切回来不会丢。若某家的地址被你改成了中转站（够不到官方域名时的常见做法），那条改动也一起记着，旁边有「恢复官方地址」可以随时还原。

### 采样参数与高级选项

- **创造性（temperature）**：设定创作建议 0.7–1.0，一致性检查与文章审校建议 0.2–0.4。
- **单次回复上限（max_tokens）**：0 = 不限制，交给厂商默认。填小了长文会被截断。
- **采样范围（top_p）**：1.00 = 不限制（多数厂商的默认值，等于不传）。一般只调 temperature 就够了。
- **流式接收**：默认开着（边写边显示）。只有网关的流式不老实（少字、乱序、莫名中断）时才建议关掉；关掉后要等整段写完才一次显示。
- **高级：直接改请求**（默认收起）：
  - **JSON 模式（`response_format`）三态** —— `自动`（按每个任务本来的需要，默认）/ `总是带上` / `从不带`。报「response_format 不支持」就选「从不带」。
  - **额外请求头**：JSON 对象。有些网关要额外的鉴权头或版本头。同名字段（不分大小写）会覆盖内置的 `Authorization`。**浏览器直连与本机转发两条路都会带上它。**
  - **额外请求体**：JSON 对象，与内置参数合并 —— 用来传厂商私有开关（DeepSeek 的 thinking、Qwen 的 `enable_thinking` 之类）。同名字段以你写的为准，唯独 `messages` 不会被覆盖。

这两栏写歪了会**就地报红、说清是哪一栏错在哪**，而且发送前会拦下来 —— 不静默忽略。

### 关于跨域（重要）

浏览器直接请求模型厂商 API 时，部分厂商或公司网络会因 CORS 策略拒绝，表现为 `Failed to fetch`。

应用已经内置了兜底：**直连失败时自动改走本机的同源转发**（`/__wf-proxy`，由 `server.mjs` 提供，只监听 127.0.0.1）。所以你用 `start.bat` / `npm start` 启动时，这条路径通常不需要你操心。

转发器**原样转发**你在「额外请求头」里写的那些头（只滤掉浏览器自带的 `Origin` / `Referer` / `Sec-*` 和逐跳头）。这一条是必须的：早先它是把请求头「重建」成固定的几个，于是同一个配置直连能用、一退回转发就悄悄没了 —— 而厂商那边只会回一句「参数不对」，极难查。

如果仍失败，右下角会给出明确原因（是网络不可达、还是转发不可用）。

### 关于读图

新建世界时上传的图片会压缩到长边 1280 后交给模型读。**纯文本模型读不了图** ——
这种情况下应用会自动去掉图片重试一次，并明确告诉你「跳过了几张图」，流程不会中断。
确定自己的模型不支持读图，可以到「设置 → AI 模型」把「允许把图片素材发给模型」关掉，省一次失败请求。

## 功能

| 模块 | 说明 |
| --- | --- |
| **新建世界** | 投喂素材 → AI 追问 → 设定草案 → 你确认；每个追问都带「点一下直接填入」的建议答案，看不顺眼可「换一批」；确认前不写库，进度自动保存可随时中断 |
| **世界总览** | 世界基本信息、创作纪律、条目/关系统计、结构体检（指出内容单薄的分类） |
| **Wiki** | **一页三支，主角是「读」** —— 原「条目库 + 杂物间」并进来的（侧栏因此只剩这一个入口，`#entries` / `#pieces` 两个老地址仍可用、刷新后还停在那一支）。**阅读**（默认）：**像翻开一本百科** —— 左边是按分类分组列开的条目目录（带搜索/状态/排序；排序决定的是**组内先后**，分类是第一优先级；鼠标停在条目上给一行摘要预览，「正在读哪一条」高亮着），右边直接摊着正文，第三栏是信息栏。一进来就摊开一条，不用先点：导语、**读书版式**的正文（Markdown 按知识库那一套排版渲染）、**本文目录**（正文本来是按 `## 概览 / ## 历史` 分节写的，那就把那几个小节名摆出来 —— 这就是「认得出 Markdown」落在界面上的地方）、**双向关联 —— 方向写进句子里**（「本条目 位于 静默湾」和「潮汐槽 位于 本条目」是两句不同的话，不用箭头让人猜）、结构化字段（分类定义过的 + 定义之外的旧键都不丢，label 用键名）、**来源资料**（没挂资料时整块不渲染，不留空框）。正文里的 `[[名字]]` 点一下跳过去、给得出「返回上一条」（**找不到会如实说，不静默**）；搜索/筛选**不会把正在读的那篇挤走**。正文底下「编辑这条」直接带你去改。**编辑**：原来那个条目库原样搬了进来 —— 分类树 / 列表、别名、标签、自定义字段、关联条目，外加一个**真正的 wiki 编辑器**（点了就套、再点就脱、改标题级别是替换不是叠加的**工具栏**；打 `[[` 就弹条目候选，**一个都不匹配时会如实说「还没有这个条目」**而不是闷着；`##` / `**粗体**` / `[[内链]]` 各自上色的**语法高亮**；Ctrl+B/I/K 与 Tab 缩进；列表里回车自动续下一项、空项回车收掉列表；点「章节」跳到那一段；表格按行列生成；右边**分栏实时预览**，`编辑 / 分栏 / 预览` 三态用的是阅读页同一套排版；底部一条字数 / 小节 / 内链；**编辑摘要**记进活动日志，日后翻得到「当时为什么改」；草稿自动存着，重开时摆一条「恢复 / 丢弃」而**不自动套上去**），以及**编辑器里那一页「时间」**（一个时间点、或一段（起始-终结 / 起始-至今，必须明说，不靠「没填终点」去猜），可写世界内纪年与纪元名、标重大程度；**不设时间就是一条普通条目**，随时可以去掉）、**批量打磨**（勾一批、选着力点、加入[任务队列](#一次点好几个右下角的任务队列)，修订进审查队列；「挑出待打磨的」按规则自动勾选并标出原因）、**每行那颗「AI 打磨」**。**杂物间**：也原样搬了进来，长文/短文/碎片/描述/剧情 + 图片/音频/视频，碎片可一句话速记、媒体可拖拽入库，说明一行不少；陈列是一面**瀑布流卡片墙**（CSS 多列，卡片高矮随内容、随图片比例真的参差，正文带预览） |
| **关系与时间** | 一页两支，共用同一份数据。**关系**：自绘力导向图；悬停节点弹信息卡、双击就地改名、右键改颜色/连线/删除；点两点即建关系；点连线改类型与方向。**时间**：把「什么时候发生了什么」画成一条轴 —— 时间**不是另一张表**，它是条目上的一个可选字段，所以轴上画的、下面列的都是同一条条目。**右手边是「还没排进去」的条目池**：拖一条到轴上任意一处就落位 —— 位置就是它的时间，不用先填表；点一下条目、再点轴上任意一处也一样，**空轴本身就当落点**（不是「暂无数据」）。落位**只写位置、不编时间文本**，节点如实画成虚线圈；要说得更细就在右侧面板里直接改（形态 / 起始 / 终结 / 纪元 / 分量 / 精确位置，改完当场生效），按住节点左右拖就能改先后；同一纪元连成色带、点图例只看那一段；分重大/一般/琐记三级；「按年代比例 / 均匀铺开」两档轴距只是两种看法，不动数据；疏密可缩放。条目一多则**先看枢纽**：圆的轻重跟着联系的多寡走，可关。**排不整齐就让 AI 排一遍**：「AI 自动排版」读一遍轴上现状 + 还没排进去的，给出一份先后方案 —— 这一下**进任务队列**（右下角看得见、可撤单、同世界不重复排），方案**先落在审查队列**里（采纳之前轴上一点不动），可以逐行勾选与改数字，采纳时**只写位置/纪元/分量，一个字的作者时间文本都不动**；已经排对了就说「没有改动」，不摆空方案 |
| **AI 工作台** | 跟一个**内置 agent** 对话，让它替你打理知识库 —— 查、建、改、连、记，你能做的它基本都能做（条目/分类/关系/世界信息/资料/杂物/设置/页面跳转）。三档「放手程度」：**计划模式**（先摆出计划，你点「执行」才落地）、**混合**（读直接做、写要确认）、**直接执行**。**查不到会停下来问你**（带可点的候选答案），而不是换个关键词一直查；你只提到一个不存在的名字时，它会**先查、再问、同时把能确定的骨架搭好送进审查**；让它「把提到过、但还没建的补全」时，它会**读正文**（不是只看索引）逐条比对，**把这次要清的账立在你眼前**（挂在会话上、切页也在），一条条勾给作者看，只提真正缺的那些，最后报数。**清单没清空它不会半路收工** —— 想收工会被追问，催不动就把「还剩几条」如实交出来；说了「接下来我还做…」却没动作，也会被说破并标出来，不让你一直等。**它记得你们刚才聊过什么**（先问「导师是谁」、再问「他的动机是什么」，那个「他」有落脚点）；把话交回来时还会顺手给几条「下一步可以让我做」，**那句话下面就是一排点一下就发生的按钮**（候选答案、底部建议泡同理）。工具名在界面上显示成人话（「新建条目」而不是 `create_entry`）。原有的「批量生成候选条目」收在本页下方的手动工具区 |
| **审查队列** | 逐条 diff 预览，采纳 / 改一改再采纳 / 驳回；支持按类型与状态筛选。**同一批跑出来的提议会自动归组，可以「采纳这一批」**；**工作台 agent 提的案带「工作台 agent 提议」来源徽标和它当时的理由**；两端未落地的关系提议会在采纳前被拦住并说明原因。**一次「AI 自动排版」是一整条提议**（类型就叫「时间轴排版」）：整张先后方案摆在一张表里，逐行勾选、逐行改位置，采纳时一条条写回、各留撤销 —— 拆成 N 条「修改条目」就丢了「这几条之间的先后」这层意思 |
| **资料库** | 上传 `txt/md/json/csv/tsv/html/yml/docx/pdf`，或**直接在线输入 / 粘贴文本**（在本页任意处按 `Ctrl+V` 也能直接存成资料）；AI 读完拆成结构化条目送入审查 |
| **一致性检查** | 扫描全部条目，找出前后矛盾的设定并给出改法。**每一轮都带着一份「已审账本」去扫** —— 报过的、你判过的，都不会换个说法再念一遍；跑完如实交代「新增几条、拦下几条、账本上还压着几条」。列表默认只看**待处理**，判过的折进「全部」里。每条问题可以单点生成修订方案（**连点好几条会排队慢慢做，不再按了没反应**），**多条时顶部会给一个「全部生成修订方案」**：按「涉及条目」分组，同一个条目上的多条问题**合并成一条修订**，已有待审修订的条目这次先放过，结果统一进审查队列 |
| **问答存档** | 只读的历史记录页 —— 追问已经统一到 AI 工作台，这里回看过去的对话，以及每条回答引用了哪些条目 |
| **操作日志** | 库里每一次写入都留一条痕：谁做的（你 / AI）、做了什么、改了哪个字段。每条都带撤销快照，可以逐步回退；可按来源与实体类型筛选 |
| **文章审校** | 粘贴剧本章节/小说片段，检查是否违背既有设定，并推荐需要补充的新条目 |
| **导出设定集** | 一键导出 Markdown / HTML 设定集（**设过时间的条目会汇总成「大事记」一章**，按时间排开、纪元换段开小节）；正文里的 `[[内链]]`、目录、关联、大事记引用都会折成**真能点、真跳得到对应条目**的链接（不再是 `[[ ]]` 方括号）；HTML 版还把表格、图片/音视频内联进去；JSON 备份与恢复 |
| **任务队列** | 右下角那枚胶囊：AI 一次只做一件，你在哪儿点一下都排进这条队，**连点好几下就是排好几件**，按点下去的顺序逐件做。正在做什么、后面还压着几件、哪件失败了为什么，都写在这枚胶囊上；展开可以撤单、重试、清空已完成。切页不丢，因为它不属于任何页面 |
| **设置** | AI 模型配置（服务商 / 型号可搜索可手填 / 采样参数 / 额外请求头与请求体 / 是否允许读图）、界面语言切换、世界管理、数据导入导出、清空数据 |

> 还没有世界时，除「设置」外的导航是灰的 —— 那些功能要先有世界才有意义。

**AI 跑起来之后可以放心走开。** 工作台 agent、资料库抽取、一致性扫描、文章审校、关系推荐、
条目扩写、批量生成、条目页的批量打磨 —— 这八处 AI 任务都活得比页面久：切页不打断，**还是回到那一页就能看到结果**
（不用重跑）。正在干活的那一页，侧栏对应项上会转一个小圈。详见
[AI 干活时，切页不会打断它](#ai-干活时切页不会打断它)。

而**「一次想点好几下」的那类活儿**（一致性检查里逐条生成修订、条目列表里逐条打磨，
以及**批量打磨里勾中的一整批**）另有去处：它们排进右下角的[任务队列](#一次点好几个右下角的任务队列)，
点几下就是排几件，进度和撤单都在那枚胶囊里，人不必守在当前页面上等 ——
批量打磨现在也走这条路，不再在页面里守着跑完。

## AI 工作台里的内置 agent

它不是「聊天窗口 + 一堆按钮」，而是真的握着改库的手。几处刻意的选择：

**协议用自定义 JSON，不用各家的原生 function calling。**
模型每轮回一个 `{"say": ..., "plan": [...], "todos": [...], "suggest": [...], "done": false}`：
`say` 是对你说的话，`plan` 是要执行的动作，`todos` 是它自己给自己立的账，
`suggest` 是「接下来可以让我做什么」，`done` 表示「这件事真的没有下文了」。
`plan` 给空数组只表示「这一轮没有动作」—— **那不等于做完**，这两件事必须分开
（见下面「不许半路收工」一段）。
这么设计是为了**只依赖「会输出 JSON」这一件事**，任何 OpenAI 兼容端点接上就能用。
（`suggest` 的**算不算数**由循环判：只有在「把话交回给作者」的那一轮才摆出来 ——
手上还有动作没跑完时，一排按钮只会让作者以为它又要自作主张。）

**但真实模型几乎必然变形，所以解析层按「只要表达了动作就必须救回来」来写。** 实测会遇到：
`plan` 写成**对象**而不是数组（只做一件事时很自然）、键名换成 `steps`/`actions`/`tool_calls`、
参数塞进 `arguments`/`params`、`plan` 被**序列化成字符串**、把 `say` 和 `plan` 吐成**两个并列的 JSON 对象**、
甚至根级直接给一个动作。这些偏差如果被当成「没给动作」丢掉，作者的感受就是
「它说完了，然后什么都没发生」，而且**无从判断是模型不想做还是解析吃了** ——
所以每一条都有对应的救回逻辑，`unit-agent-protocol.mjs` 逐条盯着（56 项）。
「安静地丢掉」是这一层最怕的事（界面一切正常，那排按钮或那批动作没了），
所以清单、建议这类字段是**能认的形状全认**：单个对象、序列化成字符串、
甚至整段用换行分开的文本都读得出来。

**最难的一类不是「写错字」，是「结构上少个括号」。** 真实翻车的一次：模型一口气提了 8 条 `create_entry`，
内容全写好了，**但每个动作对象都少写一个收尾的 `}`**（`args` 关上了、动作自己没关）。
整份输出去解析必然报错，而当时那几手救援**一个都够不着它** —— 末尾逗号没有，
截断修复只会往**末尾**补括号，少在**中间**的东西它根本看不见。
结果作者连问三轮，界面三次说「它这次没按约定的格式回」，8 条写好的提议被丢掉三次。

所以这一层补了**逐 token 的结构修复**：不再用「从最后一个逗号切下去、切出来的前缀只要能解析就算数」
这种**有损**手段，而是真读一遍 token 流，撞见不该出现的 token（最典型的就是在「该写键名」的地方
撞见 `{`）就地补一个 `}` 把当前这层收掉，再拿同一个 token 到外层重试。
**这里的次序很要紧**：有损的切尾必须排在结构修复**之后** —— 否则同一份 8 动作输出会被它从最后一个逗号处
静默切成 1 个，还报告「成功」，那才是最难查的一类 bug（界面一切正常，内容没了）。

修复本身很克制：改动次数超过 `min(64, 字符数/8)` 就放弃、老实报「没按协议」，
否则一篇随笔里随便一个 `{…}` 都能被「修」成空对象 —— **静默丢空**和**静默丢动作**是这一层最怕的两件事。
全角括号 `｛｝［］` 只在**结构判断**处按半角看待（字符串内容一个字不改），
引号的全角变体不认 —— 猜错了不如老实说读不懂。

**修好了也必须说。** 捞回来的那一轮在界面上如实标一句
「它这次 JSON 写得不合规矩（有几个地方少写了括号），我按结构补齐了 —— 动作一个没少，照常往下走」，
用中性色，跟「这一轮真的废了、已请它重说」的黄底分开。不说的话，作者会以为这模型很乖；
等下次碰上真救不回来的那一回，反倒觉得莫名其妙。

**提示词侧也堵一堵因。** 工具清单里明写：**每个动作是两层、结尾要有两个花括号**；
并建议一轮 3~5 件 —— 动作越多、每件内容越长，JSON 越容易写坏。
纠错那一轮还会专门叮嘱：要是内容太长、写到一半就断了，这一轮就少做几件（比如先建 3 条）。

**承诺了动手却没给动作，是提示词层面的坑。** 模型很爱在 `say` 里写「我先看看」然后把 `plan` 留空 ——
在这个协议里那等于**这件事就此结束**。提示词里因此明写：只要打算用工具（哪怕只是查看）就必须写进 `plan`。

**万一它还是没按格式回**（整段散文、没有 JSON），不会假装一切正常：那一轮在界面上如实标出来，
并且**自动请它重说一遍**（每个问题只纠一次，避免来回烧 token）。这是「说完就没下文」最常见的两个来源，
一个从提示词堵、一个从循环兜。

界面上这件事有**三种**说法，别混成一句：`repaired`（写歪了但我补齐了、动作照常执行）、
`retried`（没读懂，已请它重说）、`gaveUp`（纠过一次还是不行，这一轮到此为止）。
其中只有 `repaired` 用中性色（结果没问题、动作都落下了），另外两种用警示色。

**查不到就问，而不是换个关键词接着查。** 「笨」最常见的形态不是答错，是**明明缺信息却当成技术问题**：
查一次没有、改个措辞再查、还是没有、再换一个 —— 转了半天，作者只看到它在忙。
所以提示词里把话写死了：**零命中就是"信息不够"，该问不该查**。
配套地，工具给了 `ask_author`，它是**终结性**的 —— 执行到它这一轮就结束，
后面的动作一律标成「跳过」而不是硬着头皮做（不拿假设当事实）。
它也不受三档执行边界约束：**要作者先批准它提一个问题，本身就是荒谬的**。

**它记得你们刚才聊过什么。** 每一次发问对它来说都该是**接着聊**，而不是第一次见面 ——
所以系统提示词里常驻一段「我们之前聊过」：这一段会话里、**这次交代之前**的对话，
按角色标好「作者：」「你：」。没有它，作者先问「导师是谁」、再问「他的真正动机是什么」，
第二个「他」在它眼里就是凭空的（真实反馈：「我发现这里的 AI 没有上下文记忆」）。
这一份只带**人话**，不带工具回灌、也不带循环自己插的那些话
（「清单上还剩几条」那种是**系统对它说的**，带回去它会当成自己讲过的话）；
标题里还点破了一句「这是语境，不是要你重做的事」，免得它照着重做一遍。

**答完不会把话头丢回给你。** 作者原来的体验是：问「导师研究魔法与科技结合的真正动机是什么」，
它读完条目复述一遍、再抛两个「待确认：…」就完了 —— 接着做什么得他自己想。
现在把话交回来的时候（`plan` 给 `[]`，或者只是提了个问），它要顺手给 1~4 条
**下一步能做的事**（`suggest`），界面上就是那句话下面的一排按钮：**点一下就发生**。
只有**最后一条** AI 轮上的按钮可点，翻上去的会变淡禁用 —— 别让三步之前的建议
装成还在当前话题里。它也被要求**主动联想**：读到一个人名器物、而库里又没有对应条目时，
要说一句「『X』还没有条目」并给一条「构思『X』条目」的建议，而不是干问一句就完。

**"会来事"：只提到一个不存在的名字，也能把骨架搭好。** 作者说「把水位线换算连到涨潮纪」，
而这两条都还不存在 —— 干等不对，编一个更不对。agent 的做法是：**先查**（库里有没有、别名对不对），
**查不到就问**（把问题摆出来，还给可点的候选答案），**同时把能确定的部分先做出来** ——
新建条目会连摘要、标签、别名、正文大纲一起写好，直接进审查队列等着拍板。
提问与提议是同一条链上的两件事，不是二选一。

**"补全"这类活儿有明确的作业顺序。** 作者说「把提到过、但还没建的人物和物品补全」时，
最省事的偷懒是**只读条目的索引**（那上面只有标题和摘要）就下结论 —— 人名器物多半只在**正文**里，
照索引办一定漏。所以系统提示词把顺序写死了：先 `read_entry` 把相关条目的正文读进来（一轮放多个动作，
别一条一条磨）→ 拿读到的每个专有名字去库里对（含别名、含审查队列里待批的）→ **只提**确实没有、
且正文当独立实体用的那些（比喻、形容词、泛指的「某个商人」不提，拿不准的攒起来问）→
一次性给齐 `title / category / summary`，正文给大纲骨架 → 收尾报数：
读了哪几条、新提了哪几条、哪些拿不准没动，**并且不许把「已提交审查」说成「已经建好了」**。

**同一件事实质上只跑一次 —— 但只拦「成功过的那次」。** 每一轮的动作会按 `工具 + 参数` 算指纹，
拦下时**回执里引出上一次的真实结果**（不是一句「这步做过了」，那会诱导模型自己脑补成「它已经办好了」）。
两条限定都是被真实翻车逼出来的：
- **只记成功过的**。失败过的动作允许重试 —— 失败之后前提条件可能已经变了。
  作者那次就是：`create_entry` 因为「没有叫「物品」的分类」连撞三次，它自己把分类建出来之后
  **同一个动作又被当成「做过了」拦下**、回执还说「结果一样」，它就转而对作者宣称
  「这些条目的创建请求已经在审查队列中了」——而队列里一条都没有。
- **写操作作废之前的签名**（库的版本号 `worldRev`）。库变了，同一个查询的答案本来就该不一样。

连着几步都没有收获（失败 / 零命中 / 重复），它会先收到一句"你是不是卡住了"的提醒；
再空转，就直接停下来并说明**为什么停** —— 免得作者以为它还在忙。
提醒与结论都**分两种**：查不到 → 让它拿这句去问作者；动作写错了 → 让它照参数名重写。
给反了，它就会去做一件解决不了当前问题的事（细节见下面「参数名」一段）。
分类名对不上也算「写错了」那一类（报错里已经带着正确的取值清单，问作者反而把一步能改好的事推给人）。

**不许说没核实过的话。** 上面那条翻车另有一半在提示词：模型说「已在审查队列中」的时候，
它手里其实没有任何可核的东西。所以那一段被写死成两句：**不确认就去查**
（`search_entries` 查库、`list_review` 看队列），以及**别把「已提交审查」说成「已经建好了」**。
第二句原先是个**孤儿键** —— 文案写好了却没人引用，等于没写。

**不许半路收工：它得给自己立账，而且这份账作者随时看得见。**
「把提到过、还没建的补全」是**一趟要把几十条条目读完**的活，一轮读三四条也要六七轮。
作者贴过来的那趟里，20 条条目它只读了 3 条就说了句「接下来，我将继续检查其他条目……」然后收工 ——
因为循环里「`plan` 为空 = 收工」，而它 `plan` 是空的。所以补了三样：

- **`todos`：模型自己立的待办清单。** 它写进回复里，挂在会话上（切页、刷新都在），
  **每轮随系统提示词回到它眼前**，界面上也常驻摆给作者看（还剩几条、哪几条）。清单是它自己的账，
  不是界面替它演的进度条 —— 它没立就是空的。配套还有一条：**把没做完的项从清单上划掉**是最省事的
  「假装做完」，所以少掉的未完成项会被数一份、连同结果一起回灌（划掉它，它自己会看见）。
- **`done`：显式收工。** 「这一轮没有动作」和「这件事做完了」必须分开：没写 `done`、话里又是
  「我接下来还要做…」这种承诺，循环就说破它一次（`promiseNudge`）；再犯，就在界面上
  **如实标一句「这句承诺没有兑现」**，而不是留作者一个人等一个不会来的下一轮。
- **催有上限、说要有交代。** 清单上还有没勾的就想收工 → 追问（最多两次）；
  催过还不做，就把「还剩几条、是哪几条」摆出来收尾（`agent.err.todoLeft`），**不假装干完了**。
  轮数上限从 6 提到 20（清单式任务的正常长度），到顶时也报「清单上还剩几条」而不是一句
  「已经做完的部分都在日志里」。打转由前面那两道闸单独管，所以抬高上限不会放着它空转。

清单和动作**可以同一轮给** —— 「一共 5 条，我先把账立起来，现在读前 2 条」正是这么写的。
（早先的实现写的是「同一轮里给了 plan 就别动 todos」，那条规矩是错的：真实 agent 的常态就是先立账再动手，
忽略清单的话，那份账永远立不起来、模型下一轮回来也看不见自己刚才说过什么。）

**agent 自己新建的条目，一律先进审查队列，不许直接落库。**
这是"AI 提议、人拍板"这条底色在 agent 上的落法：`create_entry` / `create_relation` 产出的都是**提议**，
带 `origin: 'agent'` 来源徽标和它当时给的理由（`why`），在审查页和别的候选一起排队，采纳才入库。
几个连带的规矩：
- 提议也是写入，所以**同样可撤销** —— 撤回提议时，挂在它上面、依赖它的关系提议一并收回。
- 关系提议的两端必须都已落地才允许采纳，否则会在图谱上留下指向空条目的断头线；
  一端还在队列里时，采纳按钮**禁用并说明原因**（应用层与 store 各有一道守卫）。
- 采纳那条条目时，挂在它上面的关系会**跟着一起落地**，不用作者再手工连一次。

**批量打磨走的是同一条路。** `polish_entries` 一次最多收 8 条，产出仍然全是 `update-entry` 提议 ——
哪怕你把执行边界调到最放手的「直接执行」，它也不会自己改掉正文。
（三档边界管的是「动作要不要先问」，管不到「产出要不要审」。）

**工具指认只用标题/别名，不用 id。** 模型不该知道、也不该编造内部 id，
所有入口参数都是人类可读的名字，由 `tools.ts` 解析成 id —— 对不上会明确报错，而不是改错东西。

**参数名要印给它看，写歪了要认得出来。** 每个工具声明自己认哪些参数名（`AgentTool.args`），
这些名字会跟在工具清单后面发给模型；它真写歪了（`entry` 写成 `title`、`query` 写成 `keyword`、
键名写中文），执行前先按别名表折回规范名 —— 所以同一个动作换个说法写，还是**同一个**动作。
两个参数名折成同一个键名这类歧义**不猜**（`update_entry` 里 `title` 是「改成什么标题」，
不是「改哪一个」），照实报缺。

**缺参数时的报错必须能照着重写。** 说清三样：缺哪个、这个工具认哪些、你这次给的是什么。
这不是洁癖 —— 曾经的报错只说「缺少标题」，而模型明明写了标题、只是写在 `title` 键上，
它从这句话里读不出「你的键名我不认识」，于是**原样重试**，连试 8 次、撞上打转护栏，
整件事中止（作者的原话是「结果它根本就没补全」）。`agent.fail.missingArgs` 就是那次留下的。

**「调用写错了」和「查不到」是两件事，分岔到最后一米。** 查不到是信息不够、该去问作者；
写错了是这件事还没开始、照参数名重写就有结果。所以：失败回灌里的话不同（`resultEmpty` /
`resultBadCall`）、护栏插的话不同（`stuckNudge` / `badCallNudge`）、停下来说的话不同
（`agent.err.stuck` / `agent.err.stuckBadCall`）、**连对话里那个短标记也不同** ——
循环分得清、界面又合并回一句，等于白分。

**数据快照会过期，所以写操作之后重新取一份。** 连着做「新建条目 → 连关系」时，
第二步若还看着旧快照就找不到刚建的条目 —— 每次写操作后打一个 dirty 标记，下一个动作前重取。

**多步循环但有限度**：一件事最多来回 6 轮、每轮最多 8 个动作，超出就停下来说明情况。

**视图操作不抢方向盘**：agent 说「建议去某页」，界面渲染成一个**可点的按钮**，
而不是在你读它回复时把页面直接拽走。

**安全感来自可撤销，而不是来自模型不会犯错。** 每一次写入都落一条操作日志并附快照，
所以计划模式/混合模式里被拦下的动作、以及已经执行完的每一步，都能原样退回去。
（撤销「新建条目」时会连带清掉挂在它上面的关系，不留悬空线。）

执行边界分三档，默认最保守的一档 —— 这个产品的底色是「AI 提议、人拍板」：

| 档位 | 读操作 | 写操作 |
| --- | --- | --- |
| 计划模式（默认） | 都先摆进计划，等你点「执行」 | 同左 |
| 混合 | 立刻执行 | 等你确认 |
| 直接执行 | 立刻执行 | 立刻执行 |

三档管的是**动作要不要先问**，不管**生产出来的东西要不要审**。
所以即使在最放手的「直接执行」档，agent 新建的条目、关系也**照旧只进审查队列** ——
档位调高只是省掉"执行前点一下"，跨不过审查这道门。

**能点的按钮都点一下就发生，不必再按一次回车。** 一共三处，语义各有分工：

- **它给的「下一步」**（贴在它那句话下面，`接下来可以让我：`）—— 它自己看情况给的，
  比谁都贴身（「构思『神祇的监管』条目」「把这段动机补进『导师』正文」）。
  只有**最后一条** AI 轮上的按钮可点，翻上去的那些会变淡禁用。
- **底部那排建议**（`接着可以让它：`）—— 照你的知识库现想出来的，是它没给建议时的兜底；
  它给了建议时这一行**让位**（两排按钮叠着只会互相稀释）。
- **「它在等你回答」下面的候选答案** —— 点一下就是「我就这么答」。

唯一保留「只填不发」的是那个框里的 **「回它」**：它旁边的问题需要你自己组织语言，
替你回答没有意义。

> 「点一下就发生」不等于「点一下就改库」——发出去之后照旧走上面那三档放手程度，
> 计划模式照样先摆出来等你点「执行」。

> 工作台的对话会话存在 `chats`，操作日志存在 `ops` —— 两者都在本机库里，不联网。

## 批量打磨条目

一条条改设定很慢，改到第五条时手感和第一条已经不是一回事了。条目页的**批量打磨**
把这件事收成一次操作：勾一批 → 选着力点 → **加入队列** → 它一件接一件地改，
改好的修订自动进审查队列。

**多选之后是「加入队列」，不是「守着它跑完」。** 这在早先不是这样：批量打磨是在页面里
inline 跑完的，进度条长在面板上，你得守着这一页（至少也得切回来才看得见结果），
一点「退出批量」结果就没了。现在它和每行那颗「AI 打磨」走的是**同一条[任务队列](#一次点好几个右下角的任务队列)** ——
勾十件就是排十件，排上之后你爱去哪儿去哪儿，进度在右下角那枚胶囊上；顺带白拿了
撤单、重试、以及「一件翻车不堵住后面那些」。

**它比单条扩写更「克制」，这是刻意的。** 单条扩写时你盯着那一条，改得越丰富越好；
批量打磨你得分神连着审十几张卡，这时模型「顺手把原文重写一遍」是最糟的结果 ——
你得逐条对比两段几乎一样的正文，比不改还累。所以提示词里写死了：只改需要改的地方，
**说得过去的条目就原样返回**；原样返回的不进审查队列（多一张空 diff 就是让你多读一遍）。

**「答非所问」和「无需改动」必须分开。** 模型答非所问时，改后字段会退化成原值 ——
表面上和「它判断这条不用改」一模一样，但两件事的意义正好相反。所以那一条在队列里记成
**失败**并写出原因，而不是悄悄混进「无需改动」里。一条失手不影响其余条目，后面的照做。

**同一条不许叠两份修订。** 已经有待审修订的条目在**入队之前**就被拦下（`waiting` 那道闸，
单条与批量共用），并说明原因 —— 两份互相覆盖的修订摆在一起，你不知道该按哪份改。
已经在队列里的再点一次也排不进第二件：去重键是条目 id，只跟**还活着**的那件比。

**面板只「摘」进度，不另存一份。** 排上之后面板底部那行字（「本批 4 件：正在做 1 件、
还排着 3 件 · 已送审 2 条」）是从队列和审查表**现算**的 —— 队列把活儿清掉它就自己消失，
不会留一条过期的「本批 4 件」。另存一份状态就得操心它什么时候和队列说的不一样，
而它**迟早**会不一样。

**同批可以整批审。** 一次排出来的提议带同一个批号，审查页把它们归到一起并给
「采纳这一批」。整批采纳时，被阻塞的（关联另一端还没落地的那几条）自动跳过并说明。

**界面上能做的，agent 也能做。** 工作台 agent 有对应的 `polish_entries` 工具
（一次最多 8 条，产出同样是提议）。它那条路**跑在 agent 循环里、不走队列**，所以另外几件事由它自己管：

- 条数先卡一道：超过 8 条直接拒绝并让它分批 —— 每一条都是一次完整往返，几十条排下去
  作者要盯着干等十几分钟；
- 中止信号一路传进模型请求里：在 agent 停下的那一刻**已经跑完的那几条照常入队**，剩下的不再硬跑
  （回执会说清「做了 N 条就停的」）；
- 名字对不上的（查无此条 / 有歧义）原样退回解析器的原话让它自己纠，不猜一个近似的。

两条路的**产出完全一样**：都是 `update-entry` 提议（外加打磨时补出来的关联提议）、
都带同一个批号（审查页据此归组、给「采纳这一批」）、都只提议不落库。区别只在谁在等结果。

（队列那条路也一样点亮侧栏：活儿带着 `navKey` 排队，`useLiveJobNavs()` 把还活着的那些
汇总给侧栏，与 `useRunningNavKeys()` 取并集。页面里已经没有自己的进度条了，
那一下转圈是「哪一页在干活」唯一的线索。）

## 一致性检查：不再每次都念同一份清单

> 「每次检查冲突，结果都是一样的，永远是那几个。」

这是这页最早的样子，也是作者的原话。根子在于**审计没有记忆**：每次把世界整个送进去、
让模型从零开始找毛病 —— 同一份设定给出同一个判断，于是每一轮扫出来的都是那几条。
更让人恼火的是作者的动作也没有回流：他把一条判成「不是问题」忽略了、把另一条改完标了
「已处理」，下一轮扫它们照样原样回来。他看到不是「新发现」，是同一份清单被反复念。

现在每轮审计都带着一份**账本**（`src/ai/consist.ts`）出去，账上按「还该不该重看」分三组：

- **仍未处理** —— 不要重复报。它本来就在页面上挂着，再报一条只是同一个问题摆两张卡片。
- **作者已判定**（已处理 / 已忽略）、且相关条目此后没动过 —— 不要重复报。作者已经拍过板了。
- **可重看** —— 已判定，**但相关条目在那次判定之后又被改过**。允许重报，条件是必须写明
  「相比上次的变化」。

第三组是这套东西里唯一需要动脑的地方，而它靠的是**时间戳**而不是模型：
`entry.updatedAt > issue.createdAt` —— 这条问题提出之后，它盯着的条目有没有再被改动过。
这类机械判断正是代码该干的活：让模型去比时间戳，它只会瞎猜；让代码算好再告诉它，它就能
把力气花在「这次真的变了没有」上。顺带它也自洽地解决了误点忽略 —— 作者要是改了口径、
把条目改了，那条被忽略的问题会自己回到「可重看」里。

**模型未必听话，所以入库前还有一道。** 提示词里写了「换个说法也算重复」，但把全部希望押在
模型自觉上是不负责任的。`splitDuplicates` 会把库里已经说过的拦下来，界面如实报出拦了哪几条 ——
**不闷掉**。这里刻意做得保守：只认字面级重复（归一后相同，或一个套着另一个）。

追「换个说法」试过，追不动：同一条问题的两种说法（「烬石储量与城邦规模不匹配」/「烬石产量
撑不起城邦规模」）余弦相似度只有 0.38，而**同一批条目上两条不相干的问题**能到 0.26 ——
中间那条线窄得没法用，放宽一点就开始吃真问题。而「把真问题当成重复悄悄丢掉」比「多显示一条
重复」严重得多：后者扫一眼就过去了，前者是设定里埋着的坑，谁也不会发现。**宁可漏，不可错杀。**

**送入范围也说实话。** 这一段横幅原先写「送入全部条目的索引与正文摘要」，而代码里索引一直
卡在 80 条、正文只有单条上限没有总量上限 —— 作者照着提示去调设置，调的是个根本没生效的数
（审计压根没读 `contextLimit`）。现在索引跟着设置走，正文有总预算、按条目数平分，横幅把
「最多列几条、每条约多少字」如实写出来。总预算这件事不只是省钱：**只有单条上限而没有总量上限
时，条目一多整段上下文会爆，服务端悄悄截尾，而按 `updatedAt` 排序在前面的那批条目每轮都排在
前面** —— 于是模型每轮都只看到同一批，报出来的永远是那几个。这是作者那句抱怨的另一半根子。

**列表默认只看待处理。** 已判定的那些原先和待处理的长得一样、混在一个列表里，「怎么老这几条」
又有一半是这么来的。判过的不该再占着待办列表，但也不能抹掉 —— 折进「全部」里随时回看。

## 一致性检查：一次把好几条问题都生成修订方案

审完一遍，问题往往不是一条。逐条点「生成修订方案」点十几次很折磨，所以顶上多了一个
**全部生成修订**：一次把待处理的问题都变成修订方案，统一进审查队列。

**它按「涉及条目」分组，而不是一条问题发一次请求。** 同一个条目上叠着三条冲突时，
连着改三遍会让后一次把前一次的结果推翻 —— 你拿到的是三份互相打架的方案。
合并成一次请求，模型能一起权衡（提示词也点明了「几处改动互相牵动，一起想」）；
只有一处问题时仍然走单条那条措辞。**于是每一条修订只占队列里一个位置**，
「同一目标不叠两份待审修订」这条纪律才守得住。

**跑之前先把话说清楚。** 面板会告诉你这次能生成几条、有几条因为目标条目**已有待审修订**而先放过。
跑完的结果卡分开报四种数：生成了几条、几条问题被并进了同一条修订、
几条生成不了（相关条目在库里找不到 —— 只能你自己处理）、几条失手（可以单独重试）。
这四件事的意义完全不同，合成一句「已完成」等于什么都没说。

**跑着的时候这一页还是活的。** 面板显示「1/2 · 匠人同盟」，侧栏「一致性检查」跟着转，
**切页不打断**，切回来结果卡还在（结果必须显式存进全局任务槽 —— 这条踩过坑，见下）。
问题在生成成功时会被标记成已处理，所以回到这一页不会看到同一条冲突重复挂着；
生成不了的那几条如实留在待处理里。

**它和「审计」「单条生成」共用同一个任务槽。** 都在这一页、本来也只允许跑一件 ——
否则同一个页面上两个按钮都在转圈，你分不清哪个是哪个。

## 关系与时间

这一页有三支：**关系**（谁和谁有关）、**时间**（什么时候发生的），以及**编年**（把前者读成一条能一路读下去的
时间线）。它们合在一页，是因为问的是同一件事 —— **这条条目处在什么位置**：在图里的位置，和在时间里的位置。
后两支读的是**同一份数据**（条目上的那个可选时间字段），差别只在版式与读法，没有第二份说法。

> 「时间」与「编年」目前**并存**：前者是点轴（一条线 + 节点 + 标签分槽），后者是编年（牌面墙 + 甘特轨 + 刻度尺）。
> 留着两支是为了比对着挑 —— 定下来之后再决定撤掉哪一支、以及打开这一页时默认看哪一支。

### 条目一多，先看枢纽：圆的轻重

条目上百条之后，图谱会糊成一片 —— 几十个一样大的圆、几十行一样黑的名字，
枢纽和边角长得一模一样，等于没画。所以让**联系的多寡**去驱动两个视觉量：

- **圆的大小**：按连接数的**平方根**铺开。真实的关系网是长尾的 —— 少数枢纽牵着十几条线，
  大多数只有一两条；照原始比例铺，枢纽一格就把刻度吃光，其余全糊在最小档。开方之后
  「两条 vs 四条」才分得开。
- **圆的深浅、名字的浓淡**：这两个反而**不压缩**，按原始比例走。透明度要的就是「长尾退下去」，
  只连一条的自然淡，眼睛先落在枢纽上。名字同理 —— 边角的条目最后几乎只剩一个点，
  悬停或选中它才亮起来。

**压暗多少，看这张图有多密。** 十几个点的时候压暗毫无意义，只会把好好一张图看糊；
所以「敢压多暗」是跟着节点数走的：稀疏时谁也不压，稠密时才让长尾退到底。
而判断稀疏稠密用的是**眼前这张图** —— 被藏起来的分类、关掉的待定关系都不算数
（画面上看不见的关系，不该让圆变大）。连线也一样：线一多，先压淡「关联」两个字，指到哪条再读全。

**选中一个节点 = 聚光。** 它和直接相连的那一圈亮着、名字强制读清，与它无关的一律退到很淡。
从前那段是每个节点各扫一遍连线表（O(节点 × 连线)），改成先扫出一圈集合再查表 ——
条目一多，这正是不该浪费的地方。

**想平着看就把刻度关掉。** 右上「按联系轻重」取消勾选，圆一律一样大、名字一律看得清，
回到从前那个样子。图例末尾画着这条刻度本身（三个越来越大的圆）。

### 时间挂在条目上，不是另一张表

散在正文里的年份读不出「什么时候发生了什么」，所以条目可以带一个**可选**的时间。
但它不是新的一域：**一件「什么时候发生了什么」就是一条带时间的条目**，
不设时间就是一条普通条目。于是没有第二份说法要对齐 —— 轴上的、列表里的、图谱里的，
都是同一批条目（导出设定集那一章「大事记」也是照这个口径筛的）。

**时间是两个字段，不是一个。** 每段时间同时存 `from`（世界内纪年，作者怎么写就怎么存）
和 `at`（排序用的数值位置）。只存文本的话，「涨潮纪 9 年」会排到「10 年」后面 ——
按字符串排序对世界内纪年根本不成立。轴上的先后、间距、纪元分段，全靠 `at`。
区间还多一个 `toAt`（终点的数值位置，可选）：给了它，轴上那条横杠的长度就是**真实跨度**；
没给就只画一段固定长度的虚线 —— 它说的是「延续了一阵子」，但不用假装知道多久。

**形态是三选一，不是猜出来的。** 时间点 / 一段（起始-终结）/ 至今，写在数据里。
不靠「终点空不空」去推断：作者填过终点、后来又删掉，那份空白既可能是「至今」也可能是
「就是个时间点」—— 猜错会让轴上凭空多出一段跨度。所以形态显式存，编辑器和 agent 都明说。

### 轴上的操作

**排进轴的第一步不是填表。** 右手边那块「还没排进去」就是这个世界的条目池 ——
库里**每一条还没设时间的条目**都在里面，按分类和标题排好，可以打字搜。
拖一条到轴上任意一处，它就在那个位置上了：**位置就是它的时间**（由落点的 x 反算，
落在两条之间就是插进去，落在两端就是「再往后 / 往前一条」）。不想拖就点一下条目、
再点轴上任意一处，一样落位；拖到一半按 Esc、或点「算了」，都能退出去。
**空轴照样接得住** —— 它不是「暂无数据」，它是一个等着被填的落点。
轴底那条「+ 点这里，在这一刻新建一条」是另一回事：那是**从无到有**建一条新条目并当场排进去。

**落位只写位置，不编时间文本。** 拖进来的条目只有 `at`（轴上的数值位置），
没有 `from`（给人看的那句「涨潮纪十二年」）。这不是偷懒：作者还没说这是哪一年，
代码就没资格替他编一个。所以这些节点画成**虚线圈**，图例上也写着
「虚线圈 = 位置定了，时间文字还没写」—— 空白被如实画出来，而不是被一个猜出来的年份盖住。

**要说得更细，在面板里直接改。** 选中一条，右侧就是一组紧凑的字段：
形态（时间点 / 一段 / 至今）三选一、起始、终结、纪元、分量、**轴上的精确位置**。
点一下就落库，文本改动松手（失焦）即生效 —— 不用切页面，也不用翻进条目编辑器。
这一段读的写的就是 `store.setEntryTime`，和拖拽落位走的是同一处，
所以不存在「面板里改的和轴上画的对不上」。

**先后可以拖。** 按住节点左右拖就改了它的位置。拖动与点击落位共用同一个
「x → 位置数值」的换算，所以怎么摆都能对齐。

**两档轴距是两种看法，不是两种数据。** 「按年代比例」让间距反映位置数值的差
（十年就是比一年远），「均匀铺开」把条目一条挨一条排开（挤在一起时才看得清）。
切换只改画法，`at` 一个数都不动。

**纪元连成色带，条目分三级。** 同一纪元的条目在轴上方连成一条色带，点图例只看那一段；
重大/一般/琐记的节点大小不同 —— 重大的名字一直露着，琐记悬停才显示。

**名字不许压名字。** 两条相隔几十像素时节点是分得开的，但名字有十几个字宽、照样会叠在一起 ——
叠着的字比叠着的两个点更糟（点至少还数得出来）。所以摆位是**按标签实际宽度做首次适配**：
从轴上、往上、往下依次找第一条放得下的槽，放不下再让一层（最多让到快要压到底部那条添加带为止）。
参与占位的只有「默认就会显示名字」的节点 —— 悬停与选中是临时的，拿它们算分槽会让鼠标一划过整条轴就跳。

**选中一条就能顺手处理它。** 右侧面板念得出它的时间（不是一串裸字段），
改动当场生效；下面列出它在图谱里牵着的条目 —— 点一下就跳过去（那条也在轴上就顺带选中它，
不在就开条目编辑器）。这张清单读的就是关系表本身，**没有为了轴另存一份**，
所以图谱里改一条连线，这里立刻跟着变。想**新加**一条关系，回「关系」那一支就是 ——
时间轴这一支只管「什么时候」，不再兼任「跟谁有关」，两件事各归各的，谁都没有第二套说法。

### 排不整齐？让 AI 读一遍，给个先后方案

条目一多，「谁先谁后」就成了体力活。轴上那枚「AI 自动排版」把**轴上现在怎么排的**
和**右手边还没排进去的**一起交给模型，让它给出一份完整的先后方案。

这一下是**入队**动作，不是当场跑完：右下角那条任务队列里看得见（写着「为谁排一遍」），
切页不会断，中途能撤单；同一个世界不会同时排两遍（去重键就是世界的 id）。

**方案先落在审查队列里，采纳之前轴上一点不动。** 整张方案是一张表：一行一条，
写着「原来在哪儿 → 排到哪儿」，以及**它凭什么这么排**（依据得来自条目本身，不能是空话）。
原本在池子里的那条如实写成「未排进轴 → 111」，不编一个假的前位。
哪几条你不认，逐行取消勾选；位置想微调就在那一行上改数字（本来就是「一段」的条目，
还能顺手改终点 —— 终点不晚于起点就不带它）。采纳时写回去的只有三样：
**位置 `at`、纪元、分量**。作者写的**时间文字一个字都不碰** —— AI 没有资格替他编日期。
逐条走的是和手动改位置**同一个写入口**，所以每一步都能在操作日志里退回。

**没有改动就不摆方案。** 模型给的位置会和条目**当下的**位置对一遍账，
而且是两处对：任务里对一次（跟送进去的快照比），落库前再对一次（跟排队期间别人改过的库比）。
于是位置没变的不列、排到一半被删掉的跳过、标题对不上的如实报一句「N 个清单里对不上」；
全部已经排对时，它说的是「现在的顺序已经对了，没有改动」，而不是再摆一份一模一样的表。

### 编年：把同一份时间读成一条能看下去的线

点轴那一支是「一条线 + 一圈节点」，条目一多就只剩点位、读不出内容。**编年**换一种版式：
从上到下是**同一个时间轴的四层读法**，四层共用同一套横坐标与同一个横向滚动条：

1. **纪元带**：这个世界分成几段。名字用**宋体**，前面一个小方色块，下面一道横贯这一段全长的细色线 ——
   那道线**正好压在墙沿那根发丝线上**，于是「这一段墙属于哪个纪元」是看**墙沿的分段**，
   不是看一行悬在空中的字。段与段**首尾相接、铺满整条轴**：纪元本来就是彼此接着的
   （涨潮纪接着前潮纪，不是各占一段中间空着），分界取「上一个纪元最后一张卡」与「这一个纪元第一张卡」
   之间的中点 —— 那段空白一个事件都没有，归谁都不算错，那就对半分。点它只看这一段，再点回全部。
2. **卡片墙**：每一条的样子 —— `● 分量 · 形态`、`🕐 什么时候`、**宋体标题**、摘要、分类。
3. **甘特轨**：只留形状与跨度。点是一个菱形，一段是一根**按真实跨度长**的横条（名字压在条左端上方）；
   没给终点数值的「一段」画虚线 —— 它说的是「延续了一阵子」，但不假装知道多久；「至今」右边不封口。
   刻度线**贯穿轨道**，所以那一片浅色不是空白，是「有刻度的区间带」。
4. **刻度尺**：位置数值的标尺。刻度**按轴的实际长度定疏密**（先按「大约每 260px 一根」折算，
   再把格子取成 1 / 2 / 5 ×10^k），不是固定五根 —— 这条轴动辄三四千像素，固定五根时一屏只看得到一根。

**卡片不许重叠 —— 这是作者点名的。** 早先的写法是「横向坐标一律照实算，撞上的竖着往下一层摆」。
作者看过之后给了明确意见：**卡片不可以重叠，最好都并上，像历史博物馆里的时间线那样**。
于是这一页换了主张：

- **不挤的（绝大多数）**：中心就是它的时间，一个像素不动；
- **挤成一撮的**（同一刻、或位置差极小）：**整组紧贴着铺开**，锚在那一撮的中心上。
  一撮里的那几件事在时间上本来就分不出先后，摊开读比叠起来让人猜「底下压着几张」要诚实；
  而锚在中心意味着这一撮**仍然站在它该站的地方**，不是被搬到轴的别处。
- 谁被挪了、挪了几张，**图例里如实报数**（「N 张就地铺开」）。这一页可以取舍，但不能有含糊。

轴宽由**内容**决定（全部卡片并排所需的宽度），不由容器决定 —— 否则早期的条目会全挤在左边；
但也不能反过来按「谁也不许压谁」去算：作者只要有一对位置挨得极近（把两件事都记成 22 和 22.05 是常事），
算出来会要求几万像素的轴。所以到了上限就不再撑，剩下的极端情况交给「就地铺开」；
铺开之后画布宽度跟着放宽 —— 不给它地方，最右那一簇会被裁掉半张。
**轨上不铺开**：卡片可以为了不重叠而让位（那是版式），轨画的是数据本身，它钉在真实位置上。

**墙是墙，不是一摞卡片。** 卡片**底色与墙相同**、没有圆角、没有投影，只靠左边一根发丝线分栏：
挨着时它是中缝，拉开时它是下一栏的起头。悬停与选中都是**一层极淡的影**（不换底色、不位移）——
换了底色就又变成「白卡片」；而横向坐标是有意义的，鼠标扫过去动一两像素，作者会以为它真的在那儿。

**这一页只有一个块。** 左半是展墙，右半是**注记栏**（选中的那一条 / 还没排进去的池子）。
作者看过第一版之后说「最右侧的编年卡片不符合这个风格……和总体的布局都有些割裂」——
那一栏当时用的是通用「卡片」（圆角 + 描边 + 投影），浮在展墙旁边像个外挂控件。
现在两半是**同一张纸**：同一个底色、同高（`align-items: stretch`，所以栏线通到底，
不会出现「右栏只有上面一小块、下面全是空的」），中间只一根发丝线；注记栏里
**一条边框都不要**，分小节靠栏线与小节标题（11.5px、加字距、暗色）的层级，
池子也从「一圈圆角列表项」改成「平铺的行 + 发丝线分隔」。两边各有一条 e2e 断言守着
（右栏与展墙同高、右栏里没有圆角/投影的外壳）。

**字体不许压过版式。** 作者的下一句是「卡片和整体布局的比例中字体过大，有种头重脚轻的，
要适量留白」。卡片标题因此整体收一档（**21 / 18 / 16**，按分量），
把腾出来的地方还给留白：卡内边距 20/22/18、摘要行距 1.8、标题上方多一次停顿（12px）、
卡脚离正文 14px（免得它像摘要的一块）。标题仍是卡里最大的那个，层级一点没少 ——
少的是「先读到字很大、再读到卡里写了什么」。

**宋体只用在大字上。** 标题与纪元名走一条独立的衬线字体栈（思源宋体 → 宋体 → Windows 的 SimSun 兜底），
只在 **16px 以上**用 —— 这个字号下宋体的横细竖粗才出得来；正文一概不用它，屏幕上会累眼睛。

**「看法」不待在正文上方。** 比例 / 均匀、只看重大、疏密、重置原来堵在页头与画布之间，
作者说「有些阻挡美感」。现在常显的只有三个**动作**（新建 / AI 排版 / 显示），沉在画布**下面**的一行里、
默认压到 55% 不透明度；「看法」收进「显示」浮层 —— 调一次就不再碰的东西，不该占着正文上方的位置。

**AI 排版是同一处实现。** 这一支的「AI 自动排版」与点轴那一支共用 `useTimelineLayout` ——
入队、对账、进审查队列的规矩只有一份，两个视图的按钮不该给出两种结果。

### 旧版「时间线事件」怎么办

早期版本把时间线当成独立的一域，事件存在自己的一张表里、还抄了一份「牵涉到谁」。
这条设计已经撤掉：**旧记录会在世界打开时一次性迁成条目** —— 时间、纪元、分量、正文照带，
位置沿用原来的次序（轴上先后一点不乱），原来的「牵涉」转成关系（图谱里的连线因此没丢）。
迁完旧表清空、**只迁一次**（世界上有道闸门），并在操作日志里留痕 —— 这是替作者改库，
他得看得见。旧表本身暂时留着不动，所以这次没有升数据库版本（升版本要连累所有人的存量库）。

### 它跟着设定集一起走出去

导出 Markdown / HTML 时，「大事记」是一章：设过时间的条目**按时间排开**，
纪元换段的地方开一个小节，牵着的条目写成内链。这里刻意**不按纪元重新分组** ——
为了把小节凑整齐而重排，会把历史顺序讲乱（这条是被自己的 e2e 抓出来的：
一开始按纪元分组，断言「导出稿里的先后与轴上一致」立刻失败）。不想要这一章，导出选项里关掉。

### agent 也能读写，但只提议不落库

它有 `list_timeline`（读时间轴上有什么）和 `create_entry` / `update_entry` 上的时间参数
（`when` / `until` / `ongoing` / `era` / `weight` / `clearTime`，写进审查队列）。
提示词里明确要求**动笔之前先看一眼轴上已经有什么** —— 年代是已经定下的历史，不看就写必然打架。

两条最容易写歪的规矩，两条都在代码里钉死了：

- **「至今」必须显式说**。没给「到哪天」不等于「至今」，那是两回事。
- **位置不由它决定**（它无从知道轴上的刻度，硬猜一个数只会把它扔到十年之外）：
  解析出来的时间里**没有 `at` / `toAt`**，位置由 store 按当前轴末补齐，之后你在轴上拖。
- 还有个更细的分寸：**「这次没提时间」和「把时间去掉」是两件事**。
  前者什么也不动（否则它每改一次正文就顺手把你的时间抹了），后者得明说 `clearTime`。

## AI 干活时，切页不会打断它

AI 的任务动辄几十秒到几分钟。你不可能一直盯着它 —— 想去别的页面看看设定、
翻翻资料，回来发现它**趁你不在把话说完就断了**，那才是最气人的。

所以任务状态**不放在页面里**。原先有个隐蔽的错位：路由切换会把页面卸载，
而那个多步循环是个还没跑完的 `async` 函数 —— 它其实一直在跑、一直在往库里写，
但界面上的 loading、流式预览、计划卡随着卸载全没了；切回来时组件重新初始化成
"空闲"，看起来就像它停过。**更糟的是**输入框那时会重新变成可用，你再发一条，
就变成两个循环同时在改你的知识库。

现在这套东西的落点是：

- **`src/state/aiTasks.ts`** —— 一张模块级的任务表，`key → { 在哪个页面、进度、流式文本、结果 }`。
  它活在 React 之外，页面卸载动不了它；页面只负责订阅并渲染。
- **`src/state/agentRunner.tsx`** —— 工作台 agent 的运行器挂在 `Shell` 那一层。
  路由切换只卸载页面，Shell 一直活着，所以那个多步循环从头到尾没被打断过。
- **侧栏的转圈**就是读这张表：哪个导航项对应的页面有任务在跑，哪一格就转。

顺便解决了一件相关的事：**结果也不再丢**。以前抽取/审校跑完时页面已经卸载，
收尾的 `setResult` 打在一个不存在的组件上 —— 活儿白干了。现在结果写进任务表，
切回来结果面板还在，不用重新跑一遍。勾选也一起留着（否则会出现
"结果都在、勾全没了"，手一快就把一整批没复核的候选送进审查）。

几处刻意的取舍：

- **转圈只表示"正在跑"，不表示"在等你"**。等作者拍板时不该催 —— 那时该做的是让按钮可点。
  所以侧栏在工作台等拍板时不转。
- **任务按世界隔离**。任务起跑时记下当时的世界，读的时候对不上就按"没跑过"渲染 ——
  否则切了世界还会看到上一个世界的抽取结果，比没有结果更糟。
- **动画是定位用的**。只在对应的那一格转，否则到处都在转就等于没提示。
- 尊重 `prefers-reduced-motion`：关掉动效时换成静态环，信息一点没少。

## 一次点好几个：右下角的任务队列

有些活儿你不想一件一件等。翻条目列表时觉得五条都写得薄，或者一致性检查里三条问题都想让 AI 出修订 ——
那就该**点五下、排五件**，然后去干别的。右下角那枚胶囊就是这件事的家。

**为什么值得单做一层。** 这类单发动作原先各自调 `useAITask(key).run()`，而那个 `run()` 有条刻意的纪律：
**同一个 key 还跑着就直接返回 `null`**（防止两发结果互相覆盖）。单发场景下它是对的，可作者手快连点三条时，
后两条就**静默消失**了 —— 按钮闪一下、什么都没发生、也没有任何交代。那不是"慢"，是"按了没反应"，
比报错更让人不放心。于是把两件事拆开：`useAITask` 继续管"一个页面上一件大事"的流式状态；
**`src/state/jobQueue.ts`** 管"一堆小活儿，排队慢慢做"。

**串行，不并发。** 一次只跑一件：AI 按量计费，并发发出去多半撞上上游的速率限制、反而更慢；
更要紧的是**写库顺序会乱**（两件同时改世界，谁先落盘说不准），而作者点下去的顺序本身就是他的意图表达。

**收起态也要把话说全。** 胶囊上写的是"正在为《匠人同盟》生成修订方案，后面还有 2 件" ——
一个转圈等于什么都没说，那正是它要替代的东西。跑完变绿（"队列已清空 · 共完成 3 件"），
有失败的变红（"1 件没做成"）。展开是清单：每一件叫什么、排队中还是正在做、跑了几秒、失败原因、
撤单 / 重试。**撤单是真的省钱**：还排着队的那件从头到尾一个请求都不会发出去。

**它是通用设施，不认识业务。** 队列只知道"有一件活儿要跑"，名字（`为《X》生成修订方案`）
由发起它的功能给。目前接了两处：一致性检查里逐条"让 AI 生成修订方案"、
条目列表每行上的"AI 打磨"与**条目页的批量打磨**（勾一批 → 加入队列，见
[批量打磨条目](#批量打磨条目)）。
以后要加地方，就是一个 `enqueueJob({ label, group, dedupeKey, run, worldId, navKey })`。

**`navKey` 是给侧栏用的。** 活儿排进队列之后，页面自己往往已经没有进度条了 ——
侧栏那一格的转圈就成了"哪一页在干活"唯一还能一眼看到的地方（`useRunningNavKeys()` 管
页面内的 AI 任务、`useLiveJobNavs()` 管队列里的活儿，两者在 `App.tsx` 里取并集）。

两处刻意的取舍：

- **同一条条目上只许排一件。** 两个活儿同时改一个条目，作者会不知道按哪份改 ——
  与"全部生成修订方案"里把同一条目上的多条问题合并成一条是同一条纪律。
  被挡下的那一下会明说为什么，并指向那个批量入口。
- **做判断读队列本身，显示才读 React 快照。** 一口气连点三下时，三下都发生在 React 重渲染之前 ——
  拿快照去判断会一律判成"没人排过"，三件照样全排上（这个坑真踩过一次，
  现在由 `.dev/e2e-queue.mjs` 的第一条断言盯着）。

## AI 说"没问题"之前，先确认它确实说了

每条任务的提示词都写明了返回形状：文档抽取 `{"items": [...]}`、一致性检查 `{"issues": [...]}`、
关系推荐 `{"relations": [...]}`…… 解析层（`src/ai/parse.ts` 的 `asArray`）认的是一份**键名白名单**。

出过一回事：白名单里漏了 `issues` 与 `relations`，而提示词早就写着要这两个键 ——
于是**整份结果被静默丢空**，界面上的表现是一句「没有发现明显的设定冲突」。
作者看到的结论是"设定自洽"，实际是"我们没读懂"。这类失败最难发现，因为它长着一副成功的样子。

现在两道防线：

1. **`asArray` 认全**。提示词里出现过的列表键都登记在 `LIST_KEYS`；
   找不到既定键时，若整份返回**只有一个数组字段**就认它（模型把 `issues` 写成 `conflicts` 也救得回），
   还容忍再包一层（`{"data": {...}}`）。有多个数组字段就不猜 —— 那是真歧义，猜错比返回空更糟。
   → 改提示词的返回形状时，**记得同时去 `LIST_KEYS` 登记**，并把形状加进 `unit-parse.mjs`。
2. **「读不懂」不许冒充「没问题」**。`hasListShape()` 把两种情况分开：
   `{"issues": []}` 是**结论**（照常说"没有发现问题"）；`{"note": "一切自洽"}` 是**答非所问**，
   直接报错，别替模型下结论。`runConsistency` / `runRelations` 走的是这条严格路径。

`unit-parse.mjs`（30 项）盯着白名单与这个区分，`e2e-consist.mjs` 盯端到端 ——
包括假上游刻意吐一份「能解析、但没有列表」的 JSON，验证界面报的是错、而不是"没问题"。

## 多语言（i18n）

界面文案全部**软编码**：所有给人看的字都在语言包里，代码里不写死中文，加语言不用改业务代码。

**内置语言**：简体中文 `zh-CN`、English `en-US`。

**怎么切**：左侧「设置 → 界面语言」，可选「跟随系统 / 简体中文 / English」。切换即时生效，刷新后仍生效（偏好写在 `localStorage` 的 `worldforge:locale`；选「跟随系统」时会清掉这条并跟随浏览器语言）。`<html lang>` 与页面标题会一起同步。

**AI 提示词也跟随语言**：用英文界面时，发给模型的提示词同样是英文的，模型因此更倾向于用英文产出内容 —— 界面上看到的和模型看到的一致。提示词正文在 `src/ai/promptText/{zh,en}.ts`，由 `src/ai/prompts.ts` 填充占位符后送出去。

工作台 agent 同理：它的角色设定、工具说明、执行回执**也是语言包的一部分**（`src/i18n/locales/{zh,en}/agent.ts`，命名空间 `agent.*`）。那个文件里有两类读者 —— `agent.sys.*` / `agent.tool.*` 是给模型看的（只出现在提示词里），`agent.toolName.*` / `agent.mode.*` 是给作者看的。把它们放在一起，是为了改一处措辞时能同时看到「模型怎么理解」和「人怎么读」。

### 加一门新语言

1. 复制 `src/i18n/locales/en/` 为 `src/i18n/locales/<locale>/`，逐个文件把值改掉（目录结构必须与 `zh/` 同构）。
2. 新建 `src/i18n/locales/<locale>.ts`，照抄 `en.ts` 的写法聚合各模块。
3. `src/i18n/index.tsx` 的 `BUNDLES` 加一行；`src/i18n/core.ts` 的 `LOCALES` 加一行（`native` 用该语言自己写，`htmlLang` 会写进 `<html lang>`）。
4. 想连提示词一起翻译，再复制一份 `src/ai/promptText/en.ts`。

类型系统会盯着你：`zh` 是所有文案的**事实来源**，其它语言包都声明为
`Record<keyof typeof zh, string>` —— **漏掉任何一条 key，`npm run typecheck` 直接报错**。

### 验证

```bash
node .dev/i18n-coverage.mjs    # 静态扫描：源码里还有没有硬编码文案（有残留则退出码 1）
node .dev/e2e-i18n.mjs         # 真机验证：语言切换 / 持久化 / 起始页跟随 / 无缺失文案
```

个别确实该写死中文的地方（例如 `LOCALES` 里用中文写的语言名、开发者错误信息、检索用的停用词表），
在行尾加 `// i18n-allow` 放行即可。

## 数据存在哪

默认**全部存在本机浏览器**（IndexedDB），不上传任何服务器。这意味着：

- 换浏览器、换电脑，数据不会自动同步 —— 用「设置 → 导出备份」手动迁移。
- 清理浏览器数据会连带清掉你的世界观库 —— **请定期导出 JSON 备份**。

存储层做了适配器抽象（`src/storage/`），`rest.ts` 是云端适配器，未来要升级成「登录 + 云同步」不需要改动业务代码。

**写函数读的必须是「最新那份」快照。** store 里每个写操作都是「找出这一条 → 合并改动 → 整条写回」，
所以它手里那份 `db` 一旦是过期的，就会把别人刚写好的字段覆盖回去。这在**一次点击里写两回同一条**
的时候必然发生 —— 比如条目编辑器里「保存」紧接着「保存时间」：第二回拿到的是**点击那一刻**的
闭包，它捕获的旧条目里标题还是老的，于是「读旧条目 → 只改时间 → 整条写回」把刚存下的正文覆盖掉了。
界面上看不出任何异常，正文却悄悄退回上一版。所以 `setDb` 会**先把新值记进 `dbRef` 再交给 React**，
所有写函数一律读 `dbRef.current`：同一轮里连续写的每一回，读到的都是上一回刚写下去的结果。
（这条是被 `e2e-timeline.mjs` 抓出来的：断言「标题、时间文本、纪元都写进条目里了」红了一次 ——
现象是时间对了、标题退回去了。别把它当成测试写错了。）

  unit-args.mjs         单元测试：工具参数归一与必填自检（含 args 声明 ↔ 实际读的参数名的契约自检）
  unit-wiki.mjs         单元测试：Wiki 的派生数据（摘录跳过标题行 / 筛选口径与条目库一致 / 三档排序都以名字兜底 /
                        牵连数与自环 / 双向关联分开记 / 来源与内链目标 / 大纲认 ATX 不认 setext）
  unit-wikitext.mjs     单元测试：正文编辑层（包裹的反切换与边界 / 行前缀的替换与缩进保留 / 表格生成 /
                        高亮逐字符守恒与代码块内不认标记 / `[[` 查询与补全 / 章节切分与统计）

## 数据库打不开怎么办

如果启动时卡在「正在打开你的世界观库」或提示「打开本地数据库超时」：

1. 关掉**所有** WorldForge 标签页/窗口（包括浏览器休眠的后台标签、以及显示「正在升级数据库」的那些）。
2. 如果用的是 Edge / Chrome 且开着「关闭浏览器后继续运行后台应用」，关窗口后浏览器进程其实还活着 —— 请从浏览器菜单点「退出」，或在任务管理器里结束所有浏览器进程。
3. 回到页面点「关好了，重试」（不需要刷新）。

还不行的话，错误卡上有 **「复制诊断日志」** 按钮：把复制到的内容发给开发者，里面记录了数据库打开的每一步（请求、被阻塞、超时、以及本源下所有数据库的名字和版本），能直接定位卡在哪一步。数据不会因为这类问题丢失。

## 开发者：不花 API 费用验证 AI 链路

```bash
node .dev/mock-upstream.mjs 5190    # 假上游：模拟 OpenAI 兼容接口
node server.mjs --port 5188          # 产品本体
node .dev/e2e-onboarding.mjs http://127.0.0.1:5188/ http://127.0.0.1:5190/v1 .shots/onb
node .dev/sweep.mjs http://127.0.0.1:5188/ .shots/sweep
```

`e2e-onboarding.mjs` 会在真实浏览器里跑完整条新建世界的链路（含上传一张真图片，验证多模态确实送到了模型），
再做一次「生成 → 审查 → 采纳」回归，并把每一步截图存到 `.shots/`。

假上游默认**故意不发 CORS 头**，因此这条流程同时验证了跨域兜底转发是否生效；
它还提供 `GET /__mock-stats`，返回各分支命中次数与收到过的最大图片数，供脚本做断言。

统计是**跨脚本累加**的。`e2e-onboarding.mjs` 要断言"没有请求落到 unknown 分支"，
如果不清零，上一个脚本的计数会被算到它头上 —— 一个由"跑测试的顺序"决定的假失败。
所以脚本开跑前会先打一次 `GET /__mock-stats/reset` 把计数归零。手工排查时也可以手动打这个地址。

它还有一个**可控延迟**：`GET /__mock-delay?ms=1800` 让此后每次回包都先等一会儿
（`?ms=0` 关掉）。`e2e-ai-bg.mjs` 靠它来验证"AI 干活时切页" ——
假上游默认是瞬时回包，脚本永远抓不到"请求还没回来"的那一刻，只能靠碰运气 sleep 一个时长。
`e2e-polish.mjs` 也用它：不然四件活儿一瞬间就做完了，脚本抓不住"队列里正排着四件"那一刻
（「同一条再点一次排不进第二件」这条断言，只有在队列还活着的时候才验得到）。
`e2e-queue.mjs` 同样靠它验撤单 —— 撤单值钱的地方正是"排在队里那件一个请求都没发出去"。

**延迟和统计一样是跨脚本共享的服务端状态，用完必须还原**（设过的脚本收尾打 `?ms=0`，
不需要延迟的脚本开跑前也显式归零）。这条是踩出来的：`e2e-queue` 曾经设了 900ms 却不还原，
下一个脚本 `e2e-onboarding` 就无辜受害 —— 更要命的是它红的方式**完全指不到真凶**。
回包慢下来之后，「正在跑」的转圈卡片（也带 `ob-card` 类）被 `waitFor('.ob-card')` 抢先命中，
于是「AI 给出了它读懂什么」判 ✓、正文却还是空的，后面一连串「问题 0 个 / 按钮找不到」跟着塌。
两处都已修：脚本自己打扫干净，断言也改成**等正文真的到了**（`textContent.trim().length > 40`），
不再认「卡片出现了」这种宽条件 —— 出错时也会画卡片，只等元素存在等于把失败当成功。

打磨那条分支的假回包是**看正文长度**决定回什么的，不看"第几条"：
正文够长的原样返回（验「无需改动就不占队列位置」），薄的真被补一节。
正文里写着「畸形打磨」四个字的那条会触发"答非所问"，用来验它**不会**被当成「无需改动」。

一致性检查那几条分支靠**世界名里的触发词**分派（"多修订标记" → 一次出五条问题，
"畸形返回" → 吐一份没有列表的 JSON）。但触发词必须**和这条任务自己的形状标记一起判**
（`"issues"`）：世界名会出现在这个世界的*所有*提示词里，只认世界名的话，
同一个世界里随后跑的「全部生成修订」也会被截胡 —— 一次修订请求收到一份 issues 列表，
产出的修订内容正好等于原文，看起来就像「AI 一个字都没改」。
单条与合并版修订各有自己的分支，并**把收到的问题原样写回正文** ——
这样脚本能证实「发过去的确实是这几条」（合并有没有静默丢问题，这是唯一可靠的证据）。

**账本那两条分支，认的是「提示词里有没有账本块」本身**（`【已审账本】`）。默认那份假回复是
「一个不理会账本的模型」，照老样子回固定问题；只有世界名里出现 `账本静默标记` / `账本漏网标记`
时才演出「看到账本、按纪律返回空列表」与「看到账本、照样把老账又报一遍」。

这么设计是为了让断言**能证明账本真的进了提示词**，而不只是「界面显示了什么」：一旦账本块缺席，
路由就掉回老分支、照样回那条固定问题，那一节的断言会全挂。「漏网」那条更进一步 ——
它**把收到账本里第一行的标题原样抄回来**当重复项，所以 e2e 不必硬编码标题，
验的是「账本送到位了、里面写的正是那条老账」，外加入库那道兜底真的拦住了它。

agent 的调度只看**最后一条用户消息**（`ctx.lastUser`）—— 结果回灌那句、纠正指令、
护栏插话都会**留在历史里**，按整份文本判断会串场："纠正轮"被反复命中，看起来就像应用卡在永远等拍板。
两轮的场景（先读、再提议）因此要按"回灌过几轮"来分步，不能只看 `last` 里有没有那句标记。
时间那条分支就照这个办法分三步：先 `list_timeline` 读一眼轴上有什么、再提两条
带时间的 `create_entry`（其中一条显式 `ongoing: true`，验「至今」是明说的、不是猜的）、
最后收尾 —— 三轮都按"收到过几次结果回灌"来判定当前该走哪一步。
注意它**刻意不写 `at`**：位置是轴上的事，模型无从知道刻度，硬猜一个数只会把它扔到十年之外。

`stats.marks` 数的是**护栏插话出现过没有**：那两句只在历史消息里，界面上根本不渲染，
e2e 从 DOM 里看不到它们 —— 但"它说的到底是哪一句"很要紧（叫模型去问作者，还是叫它把参数改对），
两句给反了，模型就会去做一件解决不了当前问题的事，而那道护栏看着还挺正常。
`e2e-agent-args.mjs` 靠这两个计数断言这次插的是对的那条。

**`marks` 只回答"出现过没有"，答不了"第几轮出现的、那时候应用到底说了什么"。**
所以另有一份 `stats.agentTurns`（最多留 40 条）：每一次 agent 请求带上**这一轮带着哪句插话**
和**最后一条用户消息的尾巴**；控制台那行也印了 `turns=3 nudge=todoNudge`。
这不是洁癖 —— 有一次断言红在「循环没插那句承诺提醒」，而 `marks` 是空的，
于是只能在「它没插」和「它插了别的」之间反复推演，方向全错（真正的原因是断言自己在开跑前就读了统计）。
有了这两个数，一眼就能看出来。同一份教训还有一条**顺序**上的：多轮场景要按
「它已经说完几轮」`ctx.turns`（assistant 消息条数）分步，不要数「回灌过几句结果」——
护栏插话不占这个数，而失败批次会把回灌句数顶多，轮次就对错位了。

**`stats.history` 是给「跨轮记忆」准备的一双眼睛。** 那一段「我们之前聊过」**只发给模型、
界面上一个字都不渲染** —— 它到底带没带、带了什么，从 DOM 里根本看不到，
而「这一问记不记得上一问」恰恰是作者最直接的体感。所以假上游把**最近一次**请求里
那一段抄一份下来（`chars` + 开头 400 字），e2e 据此断言「这一问的请求里带着上一问的原话」。
`AGENT_MARKS.historyHeading` 顺带回一个计数，看哪几轮带了、哪几轮没带。

**时间轴排版那条分支是双向的**，判据是它自己的 JSON 形状（`"layout"` + `"toAt"`，两样都在才命中，
别的提示词里没有）：**第一次**给一份刻意用 111 / 222 / 333 的方案 —— 跟轴上那些小整数必定不同，
于是"这是真改动"不靠碰运气；**第二次起**把刚才读到的现状**原样回**，应用于是算出"零处改动"。
为此它要**读回提示词里的轴行**（中英两种行格式都认），条数记进 `stats.layoutParsed`，
e2e 断言 `>= 3` —— 这一条顺带证明了更要紧的事：**提示词真的把每条此刻的位置交给了模型**。

一条踩过的坑：**改了假上游必须重启那个进程**，不然 e2e 打的是旧代码。症状是"新分支根本不生效"
（日志里 `branch=unknown`）或者 `stats` 里读到一个 `undefined`（我这次就栽在 `layoutParsed` 上，
红得像是功能没接上）。跑之前打一次 `GET /__mock-stats` 看有没有新字段最省事。
另外 `--cors` 那个开关见上一节：不加时浏览器直连会被拦、应用自己回落到转发，**功能照常**
但控制台多一条 `blocked by CORS policy` —— `e2e-onboarding` 专门验这条回落路，其余脚本
把这类日志按 `e2e-onboarding` 的口径剔掉再看"有没有意料之外的报错"。

另一条同类的坑，在**断言自己身上**：点完「发送」**不能**立刻 `waitFor('[data-role=agent-send]')`。
React 把「发送」换成「停下」要过一帧，那一瞬「发送」还在 DOM 里 —— 等待于是在**开跑之前**
就返回了，紧接着读到的假上游统计只包含第一个请求。（症状：断言说「循环没插那句提醒」，
而 `stats` 里是空的。推了十几分钟，方向全错。）
**多轮场景要等的是一个只有跑起来才会有的状态**：脚本里那个 `awaitAgentDone()` 就是
「先等『停下』出现（确实在跑），再等它变回『发送』」。同理，要抓中间态（「清单立起来了、还有没勾的」）
就用带返回值的 `waitValue()`，取到的那一刻把值带回来 —— 分两次读很容易读到另一个状态。

`/__mock-*` 那几个控制端点始终带 CORS 头，只有真正被验证的协议面（`/v1/chat/completions`、`/v1/models`）
才按 `--cors` 走 —— 不这样割开的话，就会冒出一个「这个脚本只能配那种启动参数跑」的隐性耦合。
