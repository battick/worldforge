# WorldForge · 产品需求手册

> 版本：v0.3.0 · 定位：单机优先的个人世界观知识库  
> 本手册面向产品与规划视角，描述「做什么、为什么、做到什么算完成」，为后续优化升级预留空间。

## 〇、本手册怎么用

### 模块统一模板

第四部分的每个功能模块都按同一套骨架写，便于横向比对与交接：

| 条目        | 回答的问题                                |
| --------- | ------------------------------------ |
| **目标**    | 这个功能为什么存在，解决谁的什么问题                   |
| **触发与前置** | 从哪儿进来，需要什么条件才可用（没有世界 / 没配 AI 时怎么办）   |
| **主流程**   | 正常路径上会发生什么，按步骤走                      |
| **状态**    | 空态 / 加载中 / 成功 / 失败 / 依赖缺失，各显示什么      |
| **规则与边界** | 明确「不可以」做的事（这一栏是本手册的核心，边界比功能更能定义一个产品） |
| **异常与降级** | AI 不回、回错、超时、超预算时怎么办，以及不怎么办           |
| **数据落点**  | 写进哪张表、谁写的、留什么日志、能不能撤销                |
| **验收标准**  | 可测的、二值的判定条件                          |
| **待定**    | 已知没定下来的取舍，挂出来而不是藏在心里                 |

### 阅读约定

- 提到「作者」= 使用本产品的创作者本人；「模型」= 外部 AI 服务；「agent」= 内置的 AI 工作台。
- 提到「入库」= 写进正式设定库；「提议」= 落在审查队列、等待拍板。**两者必须分开读。**
- 数据实体名（如 `entries`、`review`）对应 `src/types.ts` 里的真实结构。

## 一、产品定位

**一句话：用 AI 帮你搭建与管理一个虚构世界（小说 / 跑团 / 游戏等），但所有决策权始终在你手里。**

核心场景：创作者脑子里有一个庞大的虚构世界——人物、势力、地点、历史、规则，散落在旧稿、笔记、大纲里。WorldForge 把这些散落设定**结构化沉淀**下来，并在扩充、修订、查冲突时，保证**AI 永远只提议、不擅自落库**。

贯穿全产品的两条主线：

| 主线          | 流程                               | 用户角色 |
| ----------- | -------------------------------- | ---- |
| ① 新建世界与新增词条 | 投喂素材 → AI 读懂并追问 → 统筹成草案 → 你确认才诞生 | 决策者  |
| ② 日常协作      | AI 产出候选 → 你审查拍板 → 才写入正式设定库       | 审查者  |

**底色铁律：AI 提议，人拍板。** 所有 AI 生成内容先进审查队列，采纳才入库，驳回即丢弃，也可以先改再采纳。

**两处最容易被动摇的地方，写在前面以免误解：**

1. 执行档位（计划 / 混合 / 直接执行）管的是「**动作要不要先问**」，管不到「**产出要不要审**」。即便调到最放手的档位，AI 新建的条目与关系**照旧只进审查队列**。
2. 「AI 说没问题」与「我们没读懂 AI 的回复」是两件事。任何一处把后者显示成前者，都是 bug。

## 二、核心设计原则

1. **单机优先**：数据全部存在本机浏览器（IndexedDB），API Key 只存本地，不上传任何服务器；换设备靠手动导出备份（以后可能更新）。
2. **AI 提议、人拍板**：AI 永不直接改设定集，一切产出走审查队列。
3. **AI 任务与页面解耦**：任务状态活在组件之外，切页不中断，切回来结果仍在。
4. **可撤销**：每一次写入都留操作日志与撤销快照，可逐步回退。
5. **多语言软编码**：界面文案全在语言包，加语言不改业务逻辑。
6. **通用设施**：任务队列、存储适配器、解析层等按「不认识业务」设计，便于横向扩展。
7. **失败要说话**：静默失败（界面一切正常、内容没了）是最严重的缺陷类别，优先级高于功能新增。

## 三、全局规范

### 3.1 术语表

| 术语                  | 含义                                                      |
| ------------------- | ------------------------------------------------------- |
| **世界（world）**       | 顶层容器。一个人可以有多个互不干扰的世界。                                   |
| **条目（entry）**       | 知识库最小单元：人物、地点、势力、事件、规则…… 一切设定的载体。                       |
| **分类（category）**    | 条目的分组，可自带结构化字段定义（如「人物」有「年龄」「阵营」）与图谱配色。                  |
| **关系（relation）**    | 条目之间的有向连线，带类型（隶属 / 敌对 / 位于 …）与备注。                       |
| **杂项**              | 设定之外的一切：长文 / 短文 / 碎片 / 描述 / 剧情 + 图片 / 音频 / 视频。无结构、不进审查。 |
| **资料（doc）**         | 作者上传或粘贴的原始素材文件，是条目「来源追溯」的落点。                            |
| **提议（review item）** | AI 产出、等待作者拍板的一条候选。未采纳前对设定库零影响。                          |
| **任务（AI task）**     | 一个页面内的大活儿，有流式状态，切页不丢（活在全局任务表）。                          |
| **队列任务（job）**       | 「一次点好几下」的小活儿，串行执行、可撤单、可重试（活在通用队列）。**与上面那个是两套机制。**       |
| **账本（audit book）**  | 一致性检查的审计记忆：报过什么、作者判过什么、哪些条目改过可以重看。                      |
| **入库 / 落库**         | 写进正式设定库。有别于「提议」。                                        |
| **Key**             | 条目标题的归一化形态，同一世界内**唯一**。是「条目不许重名」的硬约束落点。                 |

### 3.2 非目标（明确不做）

产品边界靠「不做什么」同样定义。以下均为**刻意不做**：

| 不做什么           | 为什么                                  |
| -------------- | ------------------------------------ |
| 不做多人协作 / 实时协同  | 单机优先，协作会引入冲突合并与权限模型，与「决策权在一个人手里」冲突   |
| 不做云端存储（当前版本）   | 隐私与复杂度取舍；已留适配器抽象，未来可加                |
| 不做直接增删改        | 任何增删改经历审问（除非用户特殊要求，ai agent会弹出警告窗确认） |
| 不做通用笔记 / 文档编辑器 | 杂项只收「与这个世界有关」的东西                     |
|                |                                      |
| 不做内容审核 / 事实核查  | 虚构世界无事实可言，AI 只负责「前后是否自洽」             |
|                |                                      |

### 3.3 写入来源模型

库里每一次写入都有且仅有三种来源，全部记在 `ops` 日志的 `actor` 上：

| 来源             | 说明                         | 是否可撤销                   |
| -------------- | -------------------------- | ----------------------- |
| `user`（作者）     | 界面上的手工操作                   | 是（带 `undo` 快照）          |
| `xx@agent`（AI） | 工作台 agent 执行写工具，**产出仍是提议** | 是；提议本身也可撤回              |
| `system`（系统）   | 数据迁移（旧时间线事件迁条目）、数据库升级      | 是，且必须在日志里留痕（替作者改库得让他看见） |
|                |                            |                         |

**所有写入共用一条纪律：** 写函数读的必须是库的最新快照（`dbRef`），不是点击那一刻的闭包。一次点击里连写两次同一条时，读旧快照会把刚存下的内容覆盖回去，且界面上毫无异常。

### 3.4 全局状态规范

每一处功能都要覆盖以下五种状态，不允许出现「没想过的状态」：

| 状态       | 要求                                                         |
| -------- | ---------------------------------------------------------- |
| **空态**   | 给出下一步能做什么的入口，而不是一句「暂无数据」。空时间轴是**落点**不是空态；空世界有引导页。          |
| **加载中**  | 说清正在做什么（「正在为《X》生成修订方案」），不只是转圈。尊重 `prefers-reduced-motion`。 |
| **成功**   | 说清**做到了什么、改了几条**，不是一个绿勾。                                   |
| **失败**   | 区分「做不到」与「还没做」：失败原因写成可执行的话（缺什么、去哪儿补）。                       |
| **依赖缺失** | 没有世界 → 除设置外导航置灰并说明；没配 API Key → 指向设置页，不静默禁用按钮。             |

**转圈只表示「正在跑」，不表示「在等你」。** 等作者拍板时不该催，那时该做的是让按钮可点。

### 3.5 AI 能力的通用契约

所有用到 AI 的功能共享以下约定，新功能接入时必须遵守：

1. **产出形状白名单**：提示词要求返回的列表键必须登记在解析层（`LIST_KEYS`），新增返回形状要同步登记 + 加测试。
2. **「读不懂」不许冒充「没问题」**：`{"issues": []}` 是结论，`{"note": "一切自洽"}` 是答非所问，后者必须报错。
3. **产出先进审查队列**，不直接落库。
4. **任务活在页面之外**：切页不中断，切回来结果仍在；结果必须显式存进全局任务槽。
5. **任务按世界隔离**：任务起跑时记下世界，读取时对不上就按「没跑过」渲染。
6. **AI 不能编造作者没说的事实**：位置可以算，时间文本不可以编。
7. **采样参数分场景**：设定创作 0.7–1.0；一致性检查 / 审校 0.2–0.4。

### 3.6 性能与容量目标

| 指标          | 目标                                                             |
| ----------- | -------------------------------------------------------------- |
| 打开本地库       | < 2s；超时有诊断日志与一键重试（见 4.15）                                      |
| 单世界条目数      | 500 条内图谱与轴交互保持流畅；圆形半径按连接数**平方根**铺开以抗长尾                         |
| 单次 AI 请求送入量 | 条目索引受 `contextLimit` 控制（默认 60 条，可调 5–500）；正文按**总预算**按条目数平分，不设单条上限而无总量上限 |
| 关系图布局       | 选中节点聚光采用「先扫一圈集合再查表」，避免 O(节点 × 连线)                              |
| 探测请求数       | 一轮自动探测默认上限 40 条，可调 / 可不封顶；连不上就收手不硬探                            |
| 队列并发        | 严格串行。并发会撞上游限流，且写库顺序会乱，而作者的点击顺序本身就是意图表达                         |

### 3.7 度量（本机可见，不联网）

产品不埋任何外发埋点。以下数字仅在本机可查，用于判断功能是否真的被用起来：

| 度量             | 口径                                       |
| -------------- | ---------------------------------------- |
| 条目 / 关系 / 杂物存量 | 世界总览的统计卡                                 |
| 提议采纳率          | 审查队列里 `accepted / (accepted + rejected)` |
| 审查队列积压         | 长期未处理的 `pending` 条数                      |
| AI 任务成功率       | 队列里 `done / (done + failed)`，含失败原因分布     |
| 一致性问题闭环率       | 已处理 / 总提出；以及「重复上报率」（账本拦下的条数）             |
| 结构体检结果         | 内容单薄的分类、未提供正文的条目占比                       |

### 3.8 测试与回归映射

新功能接入时必须补齐对应层级的验证，映射关系如下（脚本清单见 README）：

| 层级     | 覆盖内容                               |
| ------ | ---------------------------------- |
| 类型检查   | 语言包漏 key、数据模型改动（漏一条直接报错）           |
| 纯函数单测  | 解析层、提示词拼装、账本判重、参数归一、Wiki 派生数据、探测判据 |
| 静态扫描   | 源码里有没有硬编码的界面文案                     |
| 浏览器端到端 | 每个模块的正常路径 + 关键边界（见各模块「验收标准」）       |
| 假上游联调  | 不消耗 Key 地验证 AI 链路，含畸形返回、延迟、跨轮记忆    |

## 四、功能模块

### 4.1 新建世界（引导流程）

**目标**：让一个只有模糊想法的创作者，在十几分钟内得到一个结构完整、可立即开始写作的世界骨架，且全程保有否决权。

**触发与前置**：

- 无任何世界时自动进入（引导页 `StartPage`）；已有世界时从「世界管理 → 新建」进入。
- 无 AI 依赖的硬性前置，但**不配 API Key 则无法走追问与统筹**，此时应指向设置页并说明。
- 也可选「填表创建」

**主流程**：

1. **投喂素材**：旧文章 / 设定稿 / 大纲 / 笔记 / 图片（png/jpg/webp），或现场写规则。文件本地解析，图片压缩后交模型读。
2. **AI 读懂并追问**：先讲清读懂了什么、引用了来自哪份材料，再问影响世界走向的关键问题，每个附建议答案（可一键采用 / 「你来定」/ 「换一批」）；信息够了主动收口，作者也可随时喊停。
3. **统筹草案**：一次性给出世界名、一句话定位、题材、创作纪律、底层规则、分类、首批条目（含正文）、关系连线。
4. **确认生效**：草案每条可改、可删、可取消勾选，还能丢一句反馈让 AI 重写（可反复）；确认时再列出「AI 替你做过主的地方」（`openQuestions`）。  
   **确认之前数据库里没有任何世界数据**。进度自动保存、可随时中断续做。

**状态**：

| 状态   | 表现                                      |
| ---- | --------------------------------------- |
| 空态   | 引导页说明描述，并给出投喂入口                         |
| 加载中  | 分阶段说清「正在读取素材 / 正在提问 / 正在统筹」，不是统一转圈      |
| 失败   | 说明卡在哪一步（素材解析失败 / 模型无响应 / 返回不可解析），保留已填内容 |
| 依赖缺失 | 没配 Key：指向设置页，已投喂的素材保留                   |
| 中断恢复 | 草稿按 `stage` 自动持久化，重开回到原阶段               |

**规则与边界**：

1. **确认之前不写库**。草稿（`WorldDraft`）与正式库完全隔离。
2. 作者单方面向 AI 交代的话（`told`）**优先级最高**：与素材、与 AI 自己的判断冲突时以此为准。
3. 投喂的素材一并进入该世界的资料库，便于回溯每条设定的来源。
4. 条目重名在落库前拦截（`key` 唯一性）；草案阶段同名的条目要提前合并或提示。
5. 追问不可无休止：由 AI 判断收口，也可被作者叫停；累计问答跨轮保留，每次统筹都一并送给模型。

**异常与降级**：

- 文件解析不出文本 → 在素材上标 `warning` 并如实显示，不让作者以为它读进去了。
- 纯文本模型读不了图 → 自动去图重试一次，并明确告知「跳过了几张图」，流程不中断。
- 模型返回不可解析 → 如实报「没按约定格式回」并自动请它重说，**一个素材只纠一次**，避免来回烧 token。

**数据落点**：确认前只写 `WorldDraft`（草稿）；确认时批量写入 `worlds` / `categories` / `entries` / `relations` / `docs`，`actor=user`，记 `ops` 日志并带 `undo`。

**验收标准**：

1. 全程投喂 → 追问 → 草案 → 确认，确实建成世界，且**确认前查询库中世界数为 0**。
2. 草案上取消勾选的条目、关系，确认后不出现在库里。
3. 中断后重开，回到原阶段且已填内容不丢。
4. 投喂的素材在资料库里可查，条目上能看到来源追溯。
5. 图片素材确实送到了模型侧（联调脚本断言收到的最大图片数）。

**待定**：

- 追问轮数由 AI 决定，是否需要在设置里提供「追问深度」偏好 —— 未定。
- 是否允许「先建空壳、日后再补」的旁路入口 —— 当前刻意不提供，保留讨论。

### 4.2 世界总览

（仪表盘）

**目标**：一眼看清这个世界的体量与健康状况，知道接下来该补什么。以及各种可视化信息

**触发与前置**：需要存在当前世界。无世界时导航置灰。

**主流程**：展示世界基本信息、创作纪律、条目 / 关系 / 杂物统计，以及**结构体检**。

**规则与边界**：

1. 结构体检只**指出**问题（哪些分类内容单薄、哪些条目缺正文），不自动补。
2. 统计口径与 Wiki、导出保持一致，不出现三处三个数字。

**异常与降级**：提示词（`tone`）会原文注入每次 AI 生成 —— 它为空时所有生成任务照常跑

**数据落点**：只读。改世界信息写 `worlds`，`actor=user`，可撤销。

**验收标准**：统计数字与条目库实际条数一致；体检结果可点击直达对应分类。

**待定**：ai建议补充的具体条目方向，并且支持刷新

### 4.3 Wiki

**目标**：同一批设定，既能像百科一样**读**，也能像编辑器一样**改**，还能把「还没归类的东西」先放着。

**触发与前置**：需要存在当前世界。侧栏只有这一个入口；老的 `#entries` / `#pieces` 地址仍落在对应子页上（刷新后还停在那儿）。

**主流程**：三个子页共用同一份数据：

- **阅读（默认）**：左目录（按分类分组 + 搜索 / 状态 / 排序；排序只决定**组内先后**）、右正文（读书版式、本文目录、结构化字段、来源资料）、第三栏信息栏（双向关联、`[[内链]]` 可点跳转、支持「返回上一条」）。
- **编辑**：分类树 / 列表、别名、标签、自定义字段、关联条目，外加 wiki 编辑器（工具栏、`[[` 候选补全、语法高亮、快捷键、分栏预览、编辑摘要记入日志、草稿自动保存）；编辑器内一页「时间」用于设定时间点或时间段。
- **杂物间**：长文 / 短文 / 碎片 / 描述 / 剧情 + 图片 / 音频 / 视频，碎片可速记、媒体可拖拽入库；可关联条目、可置顶。

**状态**：

| 状态   | 表现                                 |
| ---- | ---------------------------------- |
| 空态   | 无条目时给出「新建条目 / 去投喂素材」的入口，不是一句「暂无数据」 |
| 内链失效 | `[[名字]]` 找不到目标时**如实说**，不静默渲染成死文本   |
| 草稿残留 | 重开时摆一条「恢复 / 丢弃」，**不自动套上去**         |
| 封面失效 | 封面引用的杂物被删时如实标「已失效」，不显示破图也不假装没事     |

**规则与边界**：

1. **条目 `key` 同一世界内唯一**，落库前拦截；改标题时 `key` 重算并重新校验。
2. 条目状态三档：`draft` / `pending` / `canon`；关系两档：`pending` / `canon`。待定的关系可在图谱里关掉不看。
3. 搜索 / 筛选**不会把正在读的那篇挤走**。
4. 分类定义之外的旧字段**不丢**（`label` 用键名兜底）。
5. 封面只存**引用**（指向杂物间的一条），不把图塞进条目 —— 同一张图可以同时是封面与插图，换图只换一处。
6. 删条目会连带删掉挂在它上面的关系（不留悬空线）；删分类会连带处理分类下的条目 —— 撤销时必须**一并恢复**，只记主对象不如不给撤销。


**异常与降级**：正文字段缺失（模型产出不完整）时照常入库并如实显示为空，不静默丢弃该字段。

**数据落点**：写 `entries` / `relations` / `pieces` / `categories`；`actor=user`；`ops` 记 `fields`（改了哪些字段）；带 `undo` 快照。编辑摘要进日志，日后翻得到「当时为什么改」。

**验收标准**：

1. 目录按分类分组，三档排序都只影响组内先后，且都以名字兜底（稳定排序）。
2. 内链点击可跳转，「返回上一条」可用；找不到目标时给出明确提示。
3. 筛选后正在读的那条不被挤走；刷新后仍停在原来那一支。
4. 草稿在重开后可恢复，且不自动套用。
5. 编辑摘要出现在操作日志里。
6. 删条目后图谱里没有指向空条目的断头线；撤销后关系一并回来。
7. 同名条目落库被拦截。

**待定**：是否要给条目加「模板」能力（按分类预填字段与正文骨架）—— 未定。

### 4.4 关系图谱

**目标**：看清「谁和谁有关」，以及谁是枢纽。

**触发与前置**：需要存在当前世界。与「时间 / 编年」同属一页，共用同一份数据。

**主流程**：自绘力导向图。悬停弹信息卡、双击改名、右键改颜色 / 连线 / 删除、点两点建关系、点连线改类型与方向。

**状态**：条目数为 0 时给出新建入口；条目上百条时启用视觉优化（圆的轻重跟着联系的多寡走，可关）。

**规则与边界**：

1. 关系是**有向**的，方向写进句子里（「A 位于 B」与「B 位于 A」是两句不同的话），不靠箭头让人猜。
2. 圆的半径按连接数**平方根**铺开（长尾分布下原始比例会把刻度吃光）；深浅与名字浓淡按原始比例走，让长尾自然退下去。**压暗程度跟着「眼前这张图」的节点数走**，稀疏时不压。
3. 被隐藏的分类、关掉的待定关系**不算数** —— 画面上看不见的关系不该让圆变大。
4. 待定关系（`pending`）可以关掉不看，关掉后不参与任何计算。
5. 关系的两端必须都存在；一端还在审查队列里的提议，采纳按钮**禁用并说明原因**。

**异常与降级**：节点过多时不做物理模拟的无限迭代，按节点数收敛；规模超出流畅阈值时提示可先隐藏部分分类。

**数据落点**：写 `relations`；`actor=user` 或 `agent`（agent 侧产出为提议）；`ops` 留痕；带 `undo`。

**验收标准**：

1. 点两点可建关系，点连线可改类型与方向，改完刷新仍在。
2. 稠密时圆的轻重生效、选中一个节点时相连一圈亮起；稀疏时自动收手（不压暗）。
3. 关掉待定关系后，它们不参与圆的大小计算。
4. 各分类可独立隐藏。

**待定**：是否需要「按关系类型筛选」与「关系类型的自定义管理」—— 当前关系类型是自由文本，未做成可管理字典。

### 4.5 时间轴与编年

**目标**：回答「什么时候发生了什么」，并让先后一眼可读。

**触发与前置**：需要存在当前世界。与「关系」同属一页，**共用同一份数据**。

> **核心设计：时间不是独立的一张表，它是条目上的一个可选字段。** 一件「什么时候发生了什么」就是一条带时间的条目；不设时间就是一条普通条目。因此图上画的、轴上列的、导出里汇总的，都是同一批条目，不存在两份说法要对齐。

**主流程**：

- **时间（点轴）**：一条轴 + 节点 + 标签分槽。右手边是「还没排进去」的条目池。拖一条到轴上任意一处即落位（**位置就是它的时间**）；也可点一下条目、再点轴上任意一处；**空轴本身就当落点**。选中一条后右侧面板可改形态 / 起始 / 终结 / 纪元 / 分量 / 精确位置。
- **编年**：同一时间轴的四层读法（纪元带 / 卡片墙 / 甘特轨 / 刻度尺），自上而下共用同一套横坐标。卡片不重叠、顺序单调；挤成一撮的整组就地铺开并如实报数。
- **AI 自动排版**：把轴现状 + 未排条目交给模型，给出一份先后方案。入任务队列，方案**先落审查队列**（采纳前轴上一点不动），逐行勾选与改数字，采纳时**只写位置 / 纪元 / 分量**。
- **AI 猜测时间**：给还没设时间的条目凭空定出「什么时候」（时间文本 + 位置）。与排版是两件事 —— 排版只动先后，猜测要**替作者定一个日期**，所以更重，各自独立进审查。

**状态**：空轴是**可落位的目标**而非「暂无数据」；条目池为空时说明「都排进去了」。

**规则与边界**：

1. **时间是两个字段，不是一个**：`from`/`to` 是世界内纪年（作者怎么写就怎么存），`at`/`toAt` 是排序用的数值位置。只存文本会让「9 年」排到「10 年」后面。
2. **形态三选一且显式存**：时间点 / 一段 / 至今。**不靠「终点空不空」去猜** —— 作者填过终点又删掉，那份空白既可能是「至今」也可能是「就是个时间点」。
3. **落位只写位置、不编时间文本**。作者还没说这是哪一年，代码就没资格替他编。这些节点如实画成虚线圈。
4. **AI 排版只写 `at` / `era` / `weight`**，作者写的时间文字一个字都不碰。唯一例外：**锁定条目**（`locked`）位置与文本联动，位置动了文本要跟着重写，否则锁定名存实亡；非锁定条目绝不写文本。
5. **「至今」必须显式说**：没给「到哪天」不等于至今。
6. **位置不由模型决定**：它无从知道轴上的刻度，硬猜一个数只会把它扔到十年之外。解析出来的时间里没有 `at`，位置由 store 按当前轴末补齐。
7. **「这次没提时间」与「把时间去掉」是两件事**：前者什么也不动（否则 AI 每改一次正文就顺手抹掉你的时间），后者要明说 `clearTime`。
8. 两档轴距（按年代比例 / 均匀铺开）**只是两种看法**，不动数据。
9. 没有 `toAt` 的「一段」画虚线 —— 它说的是「延续了一阵子」，但不假装知道多久。

**异常与降级**：

- 排版后位置没变的不列、排到一半被删掉的跳过、标题对不上的如实报「N 个对不上」。
- **全部已经排对时说「没有改动」**，不摆一份一模一样的空方案。
- 对账要**对两次**：任务里跟送进去的快照比一次，落库前再跟排队期间别人改过的库比一次。

**数据落点**：写 `entries.time`（`at` / `toAt` / `era` / `weight` / `from`）。`actor=user` 为直接写入；AI 排版经审查队列采纳后写入，走的是**和手动改位置同一个写入口**，因此每步都能在日志里退回。旧版独立「时间线事件」表在世界打开时一次性迁成条目（时间、纪元、分量、正文照带，位置沿用原次序，「牵涉」转成关系），**只迁一次**并在日志留痕。

**验收标准**：

1. 条目池包含**每一条还没设时间的条目**，可搜索。
2. 拖动落位只写 `at`，不产生时间文本；节点画成虚线圈；空轴也能落位。
3. 面板里改形态 / 纪元 / 分量当场生效，且与轴上画的一致。
4. AI 排版进队列 → 方案落审查 → **采纳前轴上一点不动** → 逐行改数字后采纳，只写位置、作者的时间文本一个字不动。
5. 零改动时报告「没有改动」，不产生空提议。
6. 刷新后位置、纪元、分量仍在。
7. 去掉时间可撤销；导出「大事记」的先后与轴上一致。
8. 旧时间线事件迁移后，原「牵涉」关系在图谱里没丢。

**待定**：

- **「时间」与「编年」两支刻意并存**，留作比对挑选，定稿后再撤一支，并决定打开这一页时默认看哪一支。**未定稿。**
- 是否需要「纪元」独立成表（当前是条目上的自由文本）—— 未定。
- 「AI 猜测时间」目前只给位置与时间文本建议，是否要给「置信度」—— 未定。

### 4.6 AI 工作台（内置 agent）

**目标**：让一个 agent 替你打理知识库 —— 增、删、改、查、建、连 —— 同时保证它说的话有据可查、它做的事可以退回去。

**触发与前置**：需要存在当前世界与可用的 AI 配置。

**主流程**：与 agent 对话，它握着改库的手。三档「放手程度」：

| 档位       | 读操作      | 写操作  |
| -------- | -------- | ---- |
| 计划模式（默认） | 先摆计划，等确认 | 同左   |
| 混合       | 立刻执行     | 等确认  |
| 直接执行     | 立刻执行     | 立刻执行 |

**状态**：

| 状态        | 表现                                                                 |
| --------- | ------------------------------------------------------------------ |
| 空闲 / 等待拍板 | **不转圈**（等作者时不该催），按钮可点                                              |
| 运行中       | 侧栏对应项转圈；切页不中断，回来结果还在                                               |
| 格式异常      | 三种说法必须分开：`repaired`（补齐了、照常执行）/ `retried`（已请它重说）/ `gaveUp`（纠过一次还不行） |
| 卡住        | 两种原因分头报：`empty`（查不到，该去问作者）/ `badCall`（动作写错了，照参数名重写）                |
| 收工但没做完    | 如实摆出「还剩几条、是哪几条」                                                    |

**规则与边界**：

1. **agent 新建的条目 / 关系一律进审查队列，不直接落库**。三档边界只管「动作要不要先问」，管不到「产出要不要审」。
2. **查不到就停下来问**（带可点的候选答案），而不是换个关键词接着查。零命中 = 信息不够，该问不该查。
3. **只提到不存在的名字时：先查、再问、同时把能确定的骨架搭好送审** —— 提问与提议是同一条链上的两件事，不是二选一。
4. **补全类任务必须先读正文再逐条比对**，不能只读索引下结论（人名器物多半只在正文里）。
5. **清单没清空不许收工**：想收工会被追问（最多两次），催不动就把「还剩几条」如实交出来；承诺了却没动作会被说破。清单挂在会话上，切页刷新都在。
6. **不许说没核实过的话**：不确认就去查；**不许把「已提交审查」说成「已经建好了」**。
7. **记得上下文**：系统提示词常驻一段「我们之前聊过」，只带人话，不带工具回灌与循环插话（否则它会把系统对它说的话当成自己讲过的）。
8. **同一动作实质只跑一次，但只拦「成功过的那次」**：失败过的允许重试；写操作会作废之前的签名（库变了，同一个查询的答案本就该不一样）。拦下时**回执要引出上一次的真实结果**，不是一句「这步做过了」。
9. **工具指认只用标题 / 别名，不用内部 id** —— 模型不该知道也不该编造 id。参数名写歪了要按别名折回规范名；两个参数名折成同一个键名这类歧义**不猜**，照实报缺。
10. **缺参数的报错必须能照着重写**：说清缺哪个、这个工具认哪些、你这次给的是什么。
11. **数据快照会过期**：每次写操作后打脏标记，下一个动作前重取。
12. **视图操作不抢方向盘**：agent 说「建议去某页」，渲染成可点的按钮，不在你读回复时把页面拽走。
13. **多步循环但有限度**：一件事最多来回若干轮、每轮最多若干个动作，超出就停下说明情况。
14. **`ask_author` 是终结性的**：执行到它这一轮就结束，后面的动作一律标「跳过」，不拿假设当事实。它也不受三档边界约束 —— 要作者先批准它提一个问题，本身就是荒谬的。

**异常与降级**：

- 真实模型几乎必然写歪 JSON（对象当数组、键名换掉、`plan` 被序列化成字符串、两个并列 JSON、根级直接给动作、动作对象少写收尾括号）。解析层按「**只要表达了动作就必须救回来**」来写，逐 token 结构修复排在「有损切尾」**之前**（次序搞反会把 8 个动作静默切成 1 个还报成功）。
- 修复很克制：改动次数超阈值就放弃并老实报「没按协议」，否则一篇随笔里的 `{…}` 都能被「修」成空对象。
- **修好了也必须说**：捞回来的那一轮如实标一句，用中性色，与「这一轮真的废了」分开。

**数据落点**：写操作经 `src/ai/agent/tools.ts`（唯一的写库入口）产出提议，落 `review`（`origin='agent'`，带 `why` 与 `sessionId`）；采纳后才写 `entries` / `relations`，`actor=agent`，`ops` 留痕并带 `undo`。对话存 `chats`。

**验收标准**：

1. 计划模式下先摆计划，点「执行」才落地；每一步可撤销。
2. agent 新建的条目落在审查队列，带来源徽标与理由；**调到「直接执行」档也照旧只提议**。
3. 查不到时停下来问并给可点候选，而不是反复换词检索。
4. 提到不存在的名字时，骨架提议确实进了审查队列。
5. 清点式任务：账立得起来、切页不丢、清单没清空不许收工、承诺没兑现要说破。
6. 参数名写歪时：别名能调通、报错能照着重写、护栏说的是对的那一句。
7. 少写括号的输出**照常执行且动作一个不少**，界面如实标注已修复。
8. 关系提议两端未落地时采纳被拦下；采纳条目时挂在它上面的关系跟着落地。
9. 跨轮记忆生效：第二次问「他的动机」时，上一问的人名有落脚点。

**待定**：

- 轮数与每轮动作上限的具体数值（当前实现为常量，是否开放给设置）—— 未定。
- 是否需要「会话历史管理」（多段会话的归档 / 搜索 / 删除）—— 当前只有会话列表，能力较弱。

### 4.7 审查队列

**目标**：所有 AI 提议的唯一「收费站」。让作者用最小的阅读成本，把一堆候选变成一堆决定。

**触发与前置**：有提议即可查看；侧栏常驻入口。

**主流程**：逐条 diff 预览 → 采纳 / 改一改再采纳 / 驳回；按类型与状态筛选；同批自动归组可「采纳这一批」；带来源徽标与理由；支持**再一次生成**（重跑原任务，可附加提示词，替换旧提议并可撤回）。

**状态**：队列为空时说明「没有待拍板的东西」；筛选后为空与真的为空要分开说。

**规则与边界**：

1. **两端未落地的关系提议在采纳前被拦下**，并说明原因（否则图谱上会留下指向空条目的断头线）。应用层与 store 各有一道守卫。
2. **同一目标不许叠两份待审修订** —— 两份互相覆盖的方案摆在一起，作者不知道该按哪份改。
3. 提议也是写入，**同样可撤销**；撤回一条提议时，挂在它上面、依赖它的关系提议一并收回。
4. 采纳条目时，挂在它上面的关系**跟着一起落地**，不用手工再连一次。
5. 「再一次生成」记的是**可复现的输入**（`source`），不是整份快照 —— 条目会变，快照一过期就重跑不出原味。被替换的旧提议完整存进 `superseded`，撤回可恢复。
6. 一次「AI 自动排版 / 猜测时间」是**一整条提议**（`timeline-layout` / `timeline-guess`），不拆成 N 条「修改条目」—— 拆开就丢了「这几条之间的先后」这层意思。

**异常与降级**：提议引用的目标条目已被删除 → 采纳时跳过并如实记账，不静默失败也不硬写。

**数据落点**：提议存 `review`；采纳后写 `entries` / `relations`，`actor=agent`（或原来源），`ops` 记 `propose` 与后续写入，带 `undo`。

**验收标准**：

1. 逐条 diff 正确反映改前改后；改一改再采纳能落作者改后的内容。
2. 按类型与状态筛选有效；同批提议归组且「采纳这一批」只采纳能采纳的，被阻塞的跳过并说明。
3. 关系提议一端未落地时采纳按钮禁用并给出原因。
4. 「再一次生成」能重跑，撤回后旧提议恢复。
5. 撤回提议时依赖关系提议一并收回。

**待定**：是否需要「批量驳回」与「按来源（agent / 批量生成 / 抽取）分开看」的独立视图 —— 当前只有类型与状态筛选。

### 4.8 资料库（库存）

**目标**：把散落的原始素材集中存放，并让它们成为条目「来源追溯」的落点。

**触发与前置**：需要存在当前世界。新建世界时投喂的素材自动进入这里。

**主流程**：上传 `txt/md/json/csv/tsv/html/yml/docx/pdf`，或在线输入 / 粘贴（页内 Ctrl+V 即存）；AI 读完拆成结构化条目送入审查。

**状态**：无资料时给出「投喂素材」入口；解析中的文件显示进度；已抽取的标 `parsed`。

**规则与边界**：

1. 资料是**只读存档**：抽取结果是提议，不改资料本身，也不自动覆盖已有条目。
2. 已抽取过的资料可再次抽取（重跑会产生新的提议，走 4.7 的去重规则）。
3. 支持的所有格式都应在上传失败时给出具体原因，而不是「上传失败」。

**异常与降级**：解析不出文本（扫描版 PDF、加密文档）→ 如实标注并可手动补充文本，不让作者以为它读进去了。

**数据落点**：写 `docs`（`text` 为抽取出的纯文本，`parsed` 标记）；抽取产出写 `review`；条目上的 `sourceRefs` 指回资料。

**验收标准**：

1. 上传、在线输入、页内 Ctrl+V 三条路径都能存下资料且刷新不丢。
2. 抽取结果进审查队列，采纳后条目上带来源追溯。
3. 各支持格式均可解析；不能解析的给出明确原因。

**待定**：资料是否需要「分文件夹 / 打标签」—— 当前只有平铺列表。PDF 扫描件是否需要 OCR —— 当前不做。

### 4.9 一致性检查

**目标**：找出设定前后矛盾的地方，给出改法，并且**不把同一份清单反复念给作者听**。

**触发与前置**：需要存在当前世界与可用 AI 配置。条目数为 0 时应提示先建条目。

**主流程**：扫描全部条目（含各种参数与信息），找出矛盾并给出改法；支持单条生成修订方案，也支持**全部生成修订**（按涉及条目分组、合并同条目的多条问题）。

**状态**：扫描中显示进度且切页不中断；跑完如实交代「新增几条、拦下几条、账本上还压着几条」；列表默认只看**待处理**，判过的折进「全部」。

**规则与边界**：

1. **核心是带账本审计**。每轮带着一份账本出去，账上分三组：
   - 「仍未处理」→ 不重复报（它本来就在页面上挂着）；
   - 「作者已判定、且相关条目此后没动过」→ 不重复报（作者已经拍过板了）；
   - 「可重看」→ 已判定但相关条目在那次判定之后又被改过，允许重报，**条件是必须写明相比上次的变化**。
2. **可重看靠时间戳判断，不靠模型**：`entry.updatedAt > issue.createdAt`。让模型比时间戳它只会瞎猜。
3. **入库前还有一道兜底**：提示词里写了「换个说法也算重复」，但不能把全部希望押在模型自觉上。解析层会拦下库里已经说过的，并**如实报出拦了哪几条，不闷掉**。
4. **判重刻意保守**：只认字面级重复（归一后相同，或一个套着另一个）。追「换个说法」试过，同一条问题的两种说法相似度可能低于两条不相干的问题 —— **宁可漏，不可错杀**。把真问题当重复悄悄丢掉，比多显示一条重复严重得多。
5. **送入范围要说实话**：索引条数跟着设置走，正文有总预算、按条目数平分。横幅把「最多列几条、每条约多少字」如实写出来。只有单条上限而无总量上限时，上下文会爆、服务端悄悄截尾，而排序在前的那批条目每轮都排在前 —— 于是模型每轮只看到同一批，报出来的永远是那几个。
6. **全部生成修订按「涉及条目」分组**，不是一条问题发一次请求。同一个条目上叠着三条冲突时连着改三遍，后一次会推翻前一次。合并后**每条修订只占队列里一个位置**。
7. 已有待审修订的条目**这次先放过**，并提前说明有几条因此跳过。

**异常与降级**：

- 模型答非所问（返回能解析但没有列表的 JSON）→ **报错，不许显示成「没有发现冲突」**。
- 生成修订的四种结果分开报：生成了几条、几条被并进同一条修订、几条生成不了（相关条目在库里找不到）、几条失手（可单独重试）。合成一句「已完成」等于什么都没说。

**数据落点**：问题存 `review`（`kind='consistency'`，带 `severity` / `relatedEntryIds` / `suggestion`）；账本状态随问题记录；修订方案产出为 `update-entry` 提议。生成成功的问题标记为已处理。

**验收标准**：

1. 扫描能出结果；**答非所问时报的是错，不是「没问题」**。
2. 账本生效：报过的老账不再来第二遍（假上游验证「看到账本就返回空列表」的分支）。
3. 「漏网」的模型（看到账本照样报老账）被入库兜底拦下，并如实报拦了几条。
4. 条目在判定后被改动 → 该问题回到「可重看」。
5. 全部生成修订按条目分组，同条目多条问题合并成一条，只占一个队列位置。
6. 已有待审修订的条目被跳过且提前说明。
7. 切页不中断，切回来结果还在。

**待定**：条目量极大（数千条）时的分批扫描策略 —— 当前靠索引上限与正文总预算兜底，未做分片。

### 4.10 问答存档

**目标**：回看过去的对话，以及每条回答引用了哪些条目。

**触发与前置**：需要存在当前世界。**追问能力已统一到 AI 工作台**，本页只读。

**规则与边界**：只读，不产生写入；引用关系与条目删除时的处理要一致（引用失效如实显示）。

**数据落点**：读 `chats`。

**验收标准**：历史对话可回看；每条回答引用的条目可点击跳转；引用失效时如实说明。

**待定**：问答存档与工作台会话（`ChatThread`）当前是两套数据，是否合并 —— 未定。

### 4.11 操作日志

**目标**：库里每一次写入都留痕，且任何一步都能退回去。

**触发与前置**：需要存在当前世界。

**主流程**：每一次写入都留一条：谁做的（`user` / `agent`）、做了什么（`create` / `update` / `delete` / `note` / `view` / `propose`）、改了哪个字段；每条带撤销快照，可逐步回退；按来源与实体类型筛选。

**规则与边界**：

1. 只存**结构化事实**（谁、对哪种东西、做了什么、对象叫什么），**面向人的措辞不落库** —— 否则切换语言后历史记录会卡在旧语言上。
2. `undo` 是**集合**而不是二选一：`remove` + `restore` + `settings` 可以同时发生（删条目连带删关系、删分类连带删条目、删世界要切回当前世界）。
3. **纯留痕（`note`）不改变任何数据**，不可撤销，如实标注。
4. 撤销「新建条目」会连带清掉挂在它上面的关系，不留悬空线。

**异常与降级**：撤销的目标已被二次修改时，如实说明「撤销会覆盖之后的改动」或拒绝执行，不静默覆盖。

**数据落点**：写 `ops`；撤销执行的是当时存的快照。

**验收标准**：

1. 每一次写入都有对应日志行，含来源、动作、实体、字段。
2. 逐步回退有效，且连带数据（关系、分类下的条目）一并恢复。
3. 按来源与实体类型筛选有效。
4. 切换界面语言后，历史日志的措辞跟着变。

**待定**：日志的保留上限与归档策略 —— 当前无上限，长期使用的库体积会持续增长。

### 4.12 文章审校

**目标**：把正在写的章节贴进来，检查它有没有违背既有设定，并提示该补哪些新条目。

**触发与前置**：需要存在当前世界与可用 AI 配置。

**主流程**：粘贴剧本章节 / 小说片段 → 检索相关设定 → 报出冲突与推荐补充的新条目。

**规则与边界**：

1. 只报**与既有设定冲突**的地方，不做文笔批改、不做事实核查。
2. 推荐的「新条目」是建议，不是自动创建 —— 要不要建由作者决定（可转交 agent 处理）。
3. 采样参数走低区间（0.2–0.4），这一任务要的是严谨不是发散。

**异常与降级**：检索零命中时不说「没有冲突」，而要说「库里没有相关设定，无法判断」—— 这两句的意义完全相反。

**数据落点**：只读 + 可选产出提议。任务状态活在全局任务表，切页不丢。

**验收标准**：能报出冲突并给出依据条目；零命中时如实说明无法判断；切页不中断且回来结果还在。

**待定**：是否需要「保存审校记录 / 多次审校对比」—— 当前不留存。

### 4.13 导出设定集

**目标**：把库里的东西变成一份能直接给人看、能带走、能存档的成品。

**触发与前置**：需要存在当前世界。

**主流程**：一键导出 Markdown / HTML 设定集；`[[内链]]`、目录、关联、大事记引用折成可点击链接；HTML 版内联表格 / 图片 / 音视频；支持 JSON 备份与恢复。

**规则与边界**：

1. **设过时间的条目汇总成「大事记」一章**：按时间排开，纪元换段的地方开一个小节。**刻意不按纪元重新分组** —— 为了把小节凑整齐而重排，会把历史顺序讲乱。
2. 大事记这一章可在导出选项里关掉。
3. 内链必须**真能跳**：导出稿里不该出现裸露的 `[[方括号]]`。
4. JSON 备份必须完整可恢复（含杂物间媒体 Blob）。

**异常与降级**：内链目标在导出时已被删除 → 折成普通文本而不留 `[[ ]]`，或如实标注失效，不做静默丢弃。

**数据落点**：只读导出；JSON 恢复为写入，走 `ops` 留痕。

**验收标准**：

1. Markdown / HTML 都能导出；HTML 版图片与音视频可正常呈现。
2. 导出稿里的 `[[ ]]` 已全部折成可点击链接。
3. 大事记的先后**与轴上一致**（按纪元重排会导致这条断言失败）。
4. JSON 备份 → 清空 → 恢复，数据完整回来（含媒体）。
5. 关掉大事记选项后，导出稿里不含该章。

**待定**：是否需要 PDF / EPUB 格式 —— 当前不做。是否需要「导出范围选择」（只导出某几个分类）—— 当前整本导出。

### 4.14 任务队列（右下角胶囊）

**目标**：让「一次想点好几下」的活儿排成队，人不必守在页面上等。

**触发与前置**：无世界依赖，但队列任务按世界隔离。

**主流程**：AI 一次只做一件，连点几下就排几件，按顺序串行执行。胶囊展示正在做什么、还压着几件、失败原因；展开可撤单 / 重试 / 清空已完成；切页不丢。

**状态**：

| 状态   | 表现                                      |
| ---- | --------------------------------------- |
| 运行中  | 说清「正在为《X》做什么，后面还有 N 件」，不是只转圈            |
| 完成   | 「队列已清空 · 共完成 N 件」                       |
| 失败   | 「N 件没做成」+ 逐条失败原因 + 重试                    |
| 排队中  | 可撤单。**撤单是真的省钱**：还排着的那件一个请求都不会发出去        |

**规则与边界**：

1. **严格串行，不并发**。并发会撞上游限流、而且写库顺序会乱 —— 作者的点击顺序本身就是意图表达。
2. **同一条条目上只许排一件**。两个活儿同时改一个条目，作者会不知道按哪份改。被挡下的要明说为什么，并指向批量入口。
3. **做判断读队列本身，显示才读 React 快照**。连点三下时三下都发生在重渲染之前，拿快照判断会一律判成「没人排过」。
4. **通用设施，不认识业务**。队列只知道「有一件活儿要跑」，名字由发起方给。新增接入点只需一次入队调用，并带上 `navKey`（点亮侧栏对应项）。
5. 活儿带着 `navKey` 排队，与页面内 AI 任务在侧栏取并集 —— 页面里已经没有自己的进度条了，那一格转圈是「哪一页在干活」唯一能一眼看到的地方。

**异常与降级**：一件翻车不堵住后面那些；失败可单独重试；已跑完的不受影响。

**数据落点**：不存业务数据，只存任务运行时状态；任务产出照各模块的规则落库。

**验收标准**：

1. 连点三下，三件都排上队（这条曾被 React 快照判断坑过，有专门断言守着）。
2. 切页不丢，回来进度与结果都在。
3. 撤单后，排队中的那件确实一个请求都没发出去。
4. 失败可重试；一件失败不影响后续。
5. 同一条目上排第二件被拦下并说明原因。

**待定**：是否需要「暂停队列」与「调整顺序」—— 当前只有撤单 / 重试 / 清空已完成。

### 4.15 设置

**目标**：把「接哪个模型、怎么接、数据怎么搬」收在一个地方。

**触发与前置**：无世界依赖。**没有世界时，除设置外的导航是灰的。**

#### 4.15.1 AI 模型

- **服务商预设**：常用 / 聚合与海外 / 本机 三组，都走 OpenAI 兼容协议。
- **型号**：内置型号只是兜底；点「选型号」去厂商 `GET /models` 拉**你这把钥匙真正能用**的清单。拉到就缓存在本机，只有点「重新获取」才再拉；可搜索；按「能对话的在前」排，非对话模型**标一句「可能不是对话模型」挪到后面**而不是藏起来；拉失败时把厂商原话摆出来，**且不把上一份好清单扔掉**；**型号永远可以手填**（自建网关 / 私有部署 / 新模型）。
- **自动探测可用性**：清单一到手自动逐个探（一个 `max_tokens: 1` 的极短请求），四态 —— 绿（真的回话了，**2xx 但内容为空不算**）/ 橙（余额或额度不足，单独一档，要做的事是去充钱不是换型号）/ 红（型号有问题）/ 灰（还没探过，**「没探完」不等于「不可用」**，所以不写结论）。悬停说明带厂商原话。
  - **向量 / 语音那类根本不探**；结论缓存 24 小时且跟着 API Key 走；连着几个连不上就收手；跑的过程中可随时停止；选中某个型号时若还没结论会单独探一次。
  - **探测上限可调**（默认 40），可勾「不限制」。每一次探测都是**一条真实请求**，所以这个数就是发给厂商的请求数，代价要作者自己认。没探到的如实报「还有 N 个没探」。
  - 入口**只有选型号面板里那一处**（就摆在探测那一行），设置页不再摆一份同样的控件 —— 同一个设置开两个门，只会让人怀疑它们是不是同一个。
- **切服务商**：每家各记一个型号，切走再切回来不丢；被改成中转站的地址也一起记着，旁边有「恢复官方地址」。
- **采样参数**：`temperature`（设定创作 0.7–1.0；一致性检查 / 审校 0.2–0.4）、`max_tokens`（0 = 不限制）、`top_p`（1.00 = 不传）。
- **流式接收**：默认开。只有网关的流式不老实（少字、乱序、莫名中断）时才建议关；关掉后等整段写完一次显示，但仍要补一次回调。
- **高级选项**（默认收起）：JSON 模式（`response_format`）三态 —— 自动 / 总是带上 / 从不带；额外请求头（JSON 对象，同名字段不分大小写覆盖内置 `Authorization`，**直连与本机转发两条路都带上**）；额外请求体（与内置参数合并，用来传厂商私有开关，**`messages` 不许覆盖**）。
- **读图**：图片压缩后交模型读；纯文本模型读不了图时自动去图重试并如实告知。可整体关闭「允许把图片素材发给模型」。
- **送入上下文**：`contextLimit` 控制单次生成送入的现有条目索引上限（默认 60 条，可调 5–500）。

**规则与边界**：额外请求头 / 请求体写歪了要**就地报红、说清是哪一栏错在哪**，发送前拦下来，不静默忽略。存的是**文本**而不是对象 —— 作者正在敲一半时那不是合法 JSON，存成对象就得丢弃或憋着不落盘。

**异常与降级**：**跨域兜底** —— 直连失败自动改走本机同源转发（`/__wf-proxy`，只监听 127.0.0.1）；转发器**原样转发**额外请求头（只滤掉 `Origin` / `Referer` / `Sec-*` 与逐跳头）。这一条是必须的：早先它把请求头「重建」成固定的几个，于是同一个配置直连能用、一退回转发就悄悄没了，而厂商只回一句「参数不对」，极难查。仍失败时给出明确原因（网络不可达 / 转发不可用）。

#### 4.15.2 界面语言

简中 / English / 跟随系统。切换即时生效并持久化（偏好写在 `localStorage`）；`<html lang>` 与页面标题同步。**AI 提示词也跟随语言** —— 用英文界面时发给模型的提示词同样是英文的。**agent 的角色设定、工具说明、执行回执也是语言包的一部分**。

#### 4.15.3 世界管理 / 数据导入导出 / 清空数据

多世界切换、导出 JSON 备份、从备份恢复、清空数据。**清空是不可逆操作**，需要二次确认。

**状态（数据库异常）**：启动时卡在「正在打开你的世界观库」或提示超时 → 引导关闭所有标签页（含浏览器后台进程）后「关好了，重试」；错误卡上有**「复制诊断日志」**，里面记录了数据库打开的每一步、以及本源下所有数据库的名字与版本，可直接定位。**数据不会因为这类问题丢失。** 数据库被其他标签页占用时，等待升级并自动恢复。

**数据落点**：AI 配置与偏好存在浏览器本地，不随世界走，也不上传；API Key 只存本地。

**验收标准**：

1. 型号可搜索、可手填；三组候选不重复；非对话模型被标出来；拉失败要报原因且不丢旧清单。
2. 切服务商各记一个型号；改过的地址要记住且可恢复官方。
3. 采样参数、额外请求头、额外请求体**真的进了请求**；JSON 模式三态生效；关掉流式仍正常工作。
4. 探测：拉完清单自动探、不污染对话计数、四态各归各位、非对话模型不探、悬停带厂商原话、结论进缓存、探测中能停、连不上就收手、**上限可调且可调成不封顶**。
5. 语言切换即时生效、刷新后仍生效、无缺失文案；提示词跟着语言走。
6. 数据库被占用 / 打开超时有明确引导与诊断日志，可一键重试。

**待定**：是否需要「导出 / 导入 AI 配置」（换设备时重配一遍很烦）—— 未定；当前会随 JSON 备份一起走，但没有单独的入口。

## 五、数据与隐私

- 默认全部存本机浏览器（IndexedDB），不上传服务器；API Key 只存本地。
- 换设备靠「导出备份」手动迁移；请定期导出 JSON 备份。
- 存储层做了**适配器抽象**（`src/storage/`），`rest.ts` 是云端适配器占位，未来升级「登录 + 云同步」不改业务代码。
- 数据按访问地址隔离 —— 因此启动器不会为已在运行的应用另起端口，否则用户会以为数据丢了。

### 数据实体一览

| 实体         | 说明                                  | 关键约束                                     |
| ---------- | ----------------------------------- | ---------------------------------------- |
| `worlds`   | 世界                                  | 多世界；含迁徙闸门 `timelineMigratedAt`          |
| `categories` | 分类                                  | 可带 `fieldDefs` 结构化字段定义与图谱配色              |
| `entries`  | 条目                                  | `key` 世界内唯一；`time` 可选；`sourceRefs` 可追溯；`cover` 只存引用 |
| `relations` | 关系                                  | 有向；两端必须存在；`pending` / `canon`            |
| `review`   | 审查提议                                | 9 种 `kind`（含 `timeline-layout` / `timeline-guess`）；带 `source` 可重跑、`batchId` 可归组 |
| `pieces`   | 杂物                                  | 文本类与媒体类；媒体以 Blob 存                       |
| `docs`     | 资料                                  | 抽取出的纯文本 + `parsed` 标记                    |
| `ops`      | 操作日志                                | 只存结构化事实；带 `undo` 快照                      |
| `chats`    | 工作台会话                               | 含 `todos`、`suggest`、工具调用留痕                |
| `drafts`   | 新建世界的共创草稿                           | **无 `worldId`**（确认前不属于任何世界）；确认前不写任何其他 store |
| `timeline` | 历史遗留 store                          | 时间已迁到条目上；仅在迁移时对旧记录做一次性删除                    |
| `settings` | 应用设置                                | AI 配置按服务商分别记忆；Key 只存本地                   |

**除 `worlds` 与 `drafts` 外，所有实体都带 `worldId`**，主键为字符串 id —— 便于未来从本地 IndexedDB 平移到云端表结构。数据库有明确的版本号（`DB_VERSION = 5`）与迁移闸门机制，旧数据自动升级，**只迁一次**。

## 六、度量与验收体系

见 3.7（度量口径）与 3.8（测试层级）。各模块的「验收标准」即端到端断言的口径来源，新增功能时必须同步补：

1. 纯函数单测（能不启浏览器就验的，一律不启浏览器）；
2. 浏览器端到端（正常路径 + 关键边界）；
3. 如涉及 AI 链路，用假上游联调，不消耗 Key。

**假上游的三条纪律**（用于联调，也用于理解 AI 链路的可测性）：

- 统计跨脚本累加，开跑前必须归零；可控延迟用完必须还原（否则下一个脚本会红在一个完全指不到真凶的地方）。
- 分支判据要认**这份任务自己的形状标记**，不能只认世界名（世界名会出现在这个世界的所有提示词里，会串场）。
- 「界面上根本不渲染的东西」（跨轮记忆、护栏插话）要靠假上游把收到的请求抄一份下来才能断言。

## 七、已预留的优化与升级空间（规划视角）

| 方向               | 预留余地                              |
| ---------------- | --------------------------------- |
| **云端同步**         | 存储适配器抽象 + REST 云端占位，升级云同步不改业务代码   |
| **多语言扩展**        | 界面文案全软编码（中文为事实来源），加语言只需复制语言包 + 注册 |
| **新 AI 厂商 / 型号** | OpenAI 兼容协议 + 型号可手填，新厂商接入零代码改动    |
| **任务队列扩展**       | 通用设施，接新功能只需一次入队调用                 |
| **时间轴版式**        | 「时间」与「编年」两支刻意并存，留作比对挑选，定稿后再撤一支    |
| **数据库升级**        | 明确的版本号 + 迁移闸门机制，旧数据自动升级           |
| **新工具接入 agent**  | 工具声明自己认哪些参数名，新增工具只需在工具箱里登记一次       |
| **新导出格式**        | 导出层与渲染层分离，内链 / 目录 / 大事记各自独立可关      |

## 八、风险与未决问题

### 风险

| 风险                 | 缓解                                      |
| ------------------ | --------------------------------------- |
| **数据在本机**          | 换浏览器 / 清浏览器数据会丢库，需引导定期备份                |
| **依赖外部 AI 服务**     | 可用性受余额、限流、型号变更影响，已用可用性探测与清晰报错缓解          |
| **AI 输出不稳定**       | 容错解析 + 如实报错（而非静默丢空）；「读不懂」不许冒充「没问题」       |
| **静默失败**           | 最严重的缺陷类别，优先级高于功能新增；每一处失败都要在界面上有对应说法      |
| **单机数据隔离**         | 数据按访问地址隔离，需防止用户误开多端口导致「数据看似丢失」           |
| **库体积增长**          | 操作日志无保留上限、杂物媒体以 Blob 存储，长期使用需关注（见 4.11 待定） |
