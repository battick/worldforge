## 功能：Wiki —— 「条目库 + 杂物间」并成的一页三支

用户诉求（分三次补全，最终版）：
「把杂物间取消，换成条目库的展示版本。现如今的条目库更像是编辑条目用的，而非展示用的，我希望更像一个
wiki 类型的数据库，或者说知识库，能够识别 md 并形成独特的只是风格。杂物间可以保留并入这个新页面的子页，
同时我希望改成滚动的多个卡片的形式。可以把条目库也并入这个新页面，作为新页面的『编辑页』，新页面叫做 Wiki。
卡片墙瀑布流多列。」

拆成的四条边界（AskUserQuestion 逐条确认）：新页面叫 **Wiki** 取代侧栏两项；**条目库并入**成为它的「编辑页」；
**杂物间并入**成为它的「杂物间」子页；卡片墙用**瀑布流多列**；「独特的知识风格」= 排版层 + 卡片认得 md。

### 一、页面结构

- `src/types.ts`：新增 `WikiView = 'display' | 'entries' | 'pieces'` + `WIKI_VIEWS` + `isWikiView()`。
  视图名用英文名词，原因是它**同时是路由别名与 agent 回执里「落在哪一支」的说法**，不能跟着界面措辞走。
- `src/pages/WikiPage.tsx`（新）：页头 + 三个子页签（`data-role="wiki-tab-{view}"`），
  `view === 'entries'` / `'pieces'` 时把 `EntriesPage` / `PiecesPage` 以 `embedded` 渲染。
- `src/App.tsx`：`Route` 里的 `entries` / `pieces` 两项删掉，加 `wiki`；
  `readHash()` 同时返回 `{ route, wikiView }`，`WIKI_ALIAS = { entries:'entries', pieces:'pieces' }`
  让**老地址仍然可用**（`hashOf()` 把 `display` 映射回 `#wiki`）；`applyView()` 用 `isWikiView` 收窄。
- `EntriesPage` / `PiecesPage` 加 `embedded?: boolean`：**不重复渲染页标题**（否则一页两个大标题），
  但**操作按钮一个不少**（`data-role="entries-actions"` / `"pieces-actions"`），
  **其余 DOM 与 `data-role` 一律不动**（e2e 与 sweep 靠它们选元素）。
  杂物间那一支还要留住 `pieces.desc` 那句「这里收什么」（并进来之后不能丢）。

### 二、卡片的「独特知识风格」落在哪

- `src/lib/wiki.ts`（新）：纯函数派生层，**不 import React、不 import 语言包**（文案由调用方给）。
  `excerptOf` / `firstProse`（跳过标题行，避免卡片上标题摆两遍）/ `matches`（口径**刻意与条目库一致**，
  同一个词在两支里必须搜得一样）/ `filterEntries` / `linkCounts`（自环只算一次）/ `sortEntries` /
  `relatedTo`（出入两向分开记，`dir: 'out' | 'in'`）/ `sourceDocs` / `findByTitle`。
- `src/lib/markdown.ts`：加 `MdHeading` / `stripInline()`（**按行**剥行内标记）/ `outlineOf()`
  —— 只认 ATX 标题、跟着代码块围栏走（`—` 在本项目里是分隔线，认 setext 会把分隔线当标题）。
- **卡片**（`WikiCard`）：分类 + 状态 + 标题 + 别名 + 摘录 + **正文大纲**（最多 4 条）+ 标签 + 元信息。
  「识别 md」的落点就是这排大纲：正文按 `## 概览 / ## 历史` 写，那就把那几个小节名摆出来。
- **瀑布流**：`.wk-wall` 用 CSS 多列（`column-width: 300px` + `break-inside: avoid`），**不是 grid** ——
  卡片内容定高，grid 会把同一行拉平、底下留一大片空白。代价是阅读顺序变成**按列**，
  所以**排序必须稳定**：`sortEntries` 三档（updated / title / links）**每一档都以标题兜底**，
  标题比较走 `localeCompare(b, 'zh-Hans-CN')`（比码位排出来是「赵钱孙李」乱序，按名字找完全对不上）。
- **阅读视图**（`WikiReader`，`<Modal size="xl">`）：导语、`.md.wiki` 正文、页内目录、双向关联、
  结构化字段、来源资料、上一条/下一条返回栈（覆盖层里跳转不换「层」，没有这个栈点进第三层就是一口深井）。
- **内链**：`[[名字]]` 可点、可退回；**找不到要说话**（`toast.warn`）—— 编辑器里那一版是静默忽略的，
  可在阅读视图里点了一下什么都没发生，作者只会以为自己点偏了。
- 关联的方向**写进句子**（「本条目 位于 静默湾」），不用箭头让人猜 —— 「A 效忠 B」与「B 效忠 A」是两句不同的话。

## 收尾：e2e-wiki 三条红断言 —— 都是脚本自己的问题，不是缺陷

`.dev/e2e-wiki.mjs`（新，48→49 项）。首跑 45/48，逐条查清：

1. **排序断言恒为假**。写法是 `JSON.stringify(${数组字面量} === JSON.stringify([...].sort(...)))` ——
   拿**数组**去 `===` 一个**字符串**，永远 false。两边都要先 `JSON.stringify` 成字符串。
   （红的样子很像「排序坏了」，实际顺序本来就是对的：残页、潮汐槽、灯塔、灯塔守、灰袍教团、静默湾、涨潮纪
   —— 实测就是 `localeCompare('zh-Hans-CN')` 排出来的那一套。）
2. **`.md.wiki h2` 永远选不中** —— 正文里的 `## 概览` 落成 **`h3`**：`MarkdownView` 把 `#` 留给了页面标题
   （`renderMarkdown` 里 `level = h[1].length + 1`）。`.md.wiki` 那套排版 h2/h3 都覆盖到了（CSS 里两条都有），
   所以这不是「排版没生效」。断言改成查 `.md.wiki h3` 的条数 + 容器在不在。
3. **「来源资料」查错了条目** —— 预置数据里挂了 `sourceRefs: ['dc_1']` 的是**灯塔守**，而这一节读的是**灯塔**
   （它没有 sourceRefs）。把正向断言挪到下一节（打开灯塔守那一节），
   在原地补一条**反向**断言：没挂资料时那一块**整块不渲染**（不摆一个空标题让人以为资料丢了）。

### 1. Wiki 阅读支重做成三栏百科版式（`src/pages/WikiPage.tsx`）

- `WikiCard` 整个删掉；`excerptOf` 唯一的消费者变成目录项的 `title`（函数保留，注释口径改成「悬停预览」）。

### 这一轮踩到的坑（都已写进 MEMORY.md）

- **高亮副本只能改颜色**。给某段加 `font-weight: 700` 会让它比同位置的输入框文字更宽，副本自己先折行 →
  从那一行往下全错开。而它错开的样子特别像「字体没加载好」，很难往「字重」上想。
- **中文输入法组字期间必须把文字颜色还回去**并隐藏副本：未上屏的拼音是浏览器画在 textarea 里的，
  它透明就等于「打字的时候看不见」。
- **浮层要断言「看得见」而不是「元素存在」**。候选面板钉在编辑区左下角，编辑区 320 高，在弹窗里
  这位置正好落在可视区外 —— DOM 查询一切正常、截图里却像「什么都没弹」。修法 `scrollIntoView({block:'nearest'})`
  + 断言量 `getBoundingClientRect` 与 `innerHeight`。
- **行内扫描器「没匹配就收工」会漏高亮**：`这是**粗体**` 的第一个字就不是标记开头，一收工整行全成纯文本。
  得先跳到下一个可能的起始字符，中间那截一次性当纯文本吐掉。
- **工具栏动作的「族」必须由纯函数层统一 export**（`PREFIX_MARK`）。无序与有序共用一个 mark，
  否则「点有序列表」会把无序叠成 `1. - x`。**缩进要单独拿出来算**（前缀加在缩进之后、脱掉时还回去），
  否则「取消列表」会把嵌套层级一起吃掉。
- **`en/*.ts` 的键完整性守卫要手动加**：每个英文包顶上都有 `const en: Record<keyof typeof zh, string> = {`，
  我新加的 `en/editor.ts` 与上一轮的 `en/wiki.ts` 都漏了 —— 漏了的话英文包缺 key 只能在运行期才发现。
  补上后 tsc 通过，等于顺手验了这两个包键是全的。

### 6. 型号可用性自动探测（本轮新需求）

作者原话：「希望 api 模型能在**选取模型型号或者刷新**的时候自动进行测试来确定哪个通道是可通过的，因为我这个渠道

### 7. 探测上限改成可配置（作者追问「为什么最多 40」）

作者原话：「为什么最多侦测40个？我希望能够自定义设置，默认40十个，可以选择无上限或者任意一一个」→ 追加一条

  聚合站清单动辄一两百条；更要紧的是**限流** —— 中转站在短时总量上翻脸很快，被限流耽误的是作者自己那几轮对话。
  被截掉的不是丢弃，是如实报成「还有 N 个没探」。默认保守 + 上限交给作者，是唯一说得通的取舍。
- 落地：`AISettings` 加 `probeLimit?` + `probeUnlimited?`（两个**可选**字段，老存盘数据没有 → 合并默认值）；

### 这一轮踩到 / 认清的

- **类名撞车会静默毁掉一整块界面**（最贵的一课）：编年工具栏那个 `div` 我写了
  `className="row chron-bar"`，而 `.chron-bar` 是**甘特轨区间条**的类名（绝对定位 + 9px 高 + `overflow: hidden`）

  改法：工具栏改名 `.chron-tools`，并在 CSS 那条规则上写明「这个名字是区间条专用的」。
- **判断「谁压住谁」不能靠截图，也不能靠比矩形**：第一次写的版式自检用「矩形包含对方就当父子跳过」，
  偏偏横幅盖住工具栏时横幅的矩形**正好把工具栏套在里面** → 判定成父子、报「无交叠」。
  改成**只认 DOM 的 `contains()`** 之后立刻抓住；另外加了「工具栏必须在正常流里、且高度 ≥ 28px」这条硬断言
  （被压扁是没法从「有没有交叠」里看出来的 —— 压扁之后谁都不压谁，只是全都裁没了）。
  演示脚本现在版式没过就退出码 1。
- **`Page.captureScreenshot` 的 `clip` 必须配 `captureBeyondViewport: true`**：不配会画出**不在 DOM 里**的色块

  右边一律被裁掉 —— 截出来像布局坏了，那是我自己造的假象。
- **轴宽不能按「谁也不许压谁」算**：一对挨得极近的 `at`（演示数据里的 22 与 22.05）折算出来要

  → 截图里只看得见「这里没东西」，看不出「卡片一多好不好看」。压到 25~36 之后才评得出版式。

## 编年（续）：作者看过第一版之后的意见 —— 卡片不许重叠、控件别挡美感

作者原话：

> 「卡片不可以重叠，最好都并上，或者说背景和卡片一个颜色，就像历史博物馆里的时间线一样，
>   最上面的一些配置按钮，配置文本框之类的有些阻挡美感，再想想招给别这么显眼」

### 摆位换了主张：从「宁可重叠也不挪」到「绝不重叠、挤的就地铺开」

第一版是「横向 x 一律照实算，撞上的竖着分泳道（区间图着色）」——作者要的不是这个。
新的 `placed`：先按**理想矩形相交**分簇，簇内**紧贴铺开**（`GAP` 20 → **0**）、锚在首尾两张理想中心的**中点**，
再往后让一下保证不越过前一簇；`pushed` 记被挪的张数，**图例如实报数**。
理由写进了代码：一撮里的几件事在时间上本来就分不出先后，摊开读比叠起来让人猜「底下压着几张」诚实；
锚在中点意味着那一撮仍站在它该站的地方。

配套两条：
- **画布宽要跟 `placed.right` 取大值**。铺开是在坐标体系里做位移，最右一簇会探出内区 —— 不取大值就裁掉半张。
- **轨上不铺开**：卡片可以让位（那是版式），轨画的是数据，`railLeftOf` 用真实中心。两者挤的那一小段会差开，
  这是这一页唯一一处「看得见的取舍」，所以名字上就分开（`leftOf` / `railLeftOf`）。

### 视觉：从「白牌面浮在台面上」到「一整面展墙」

- 卡片 `background: transparent`、去掉圆角与投影，只留 `border-left` 一根发丝线 —— **挨着时是中缝，拉开时是下一栏的起头**。
- `.chron-card` 方角、无描边、无投影（`--bg-soft` 一整面）。
- hover / sel 只加一层极淡的影（`rgba(47,111,176,.05/.08)`），**不换底色、不位移**。
- 删掉「叠两张时的 3px 台面色垫子」（不重叠了就不需要）。

### 控件：从「堵在画布上方」到「沉到底下一行」

- 工具条整块搬到**画布下面**（`.chron-footbar`）：常显只有三个动作（新建 / AI 排版 / 显示），都是无边框、字号 12、
  默认 `opacity: .55`（hover 才浮出来）。
- 「看法」那一类（比例 / 均匀、只看重大、疏密、重置）收进**「显示」浮层**（`.chron-more`，从下往上弹 + 全屏透明遮罩点别处收起）。
  **踩到的坑**：浮层长在 `.chron-tools` 里，被父级那 55% 一起压暗 → 浮层开着时给父级加 `.open` 恢复满不透明。
  另一个：`疏密` + 缩放挤在一行会被压成竖排的两个字 → 一行一件事。
- 池子空的时候不再摆一张写着「0 条」的白卡，一行细字就够。
- 图例里的「按住卡片左右拖」删掉 —— 页头那句说明里已经有了，重复只会把这一行撑长。

### 刻度尺与轨道

- 刻度**按轴长定疏密**：`raw = span×260/inner` → 取 1/2/5×10^k（原来固定五根，而这条轴三四千像素，一屏只看得到一根）。
- 刻度线**贯穿轨道**（`.chron-gridline`，用 `--border-strong`，`--border` 在浅底上看不见）：
  区间按行摆，可见的行常常只有一两条，没网格就是一大片「像没画完」的空白。
- `RAIL_ROW` 34 → 30、`BAR_TOP` 30 → 26（多出来的都是空）。
