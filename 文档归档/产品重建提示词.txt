# WorldForge · 重建提示词（复制全文，作为一条消息发给新 AI）

> 用法：把下面「提示词正文」里的内容整段复制，作为新会话的**第一条消息**发给一个具备代码执行能力的 AI。
> 它能重建出一个**功能等价**的 WorldForge（同一套数据模型、同一套边界纪律、同一批模块），但不会逐字节复刻原实现 —— 若要逐行还原，请把 `src/` 源码一并交给它作为参考。
> **注意**：不要把它当成「一句话生成整个产品」的咒语；请配合第 12 节的里程碑分阶段推进。

1. 技术栈（锁死，不要替换）
════════════════════════════════════════════
React 18.3 + TypeScript 5.6 + Vite 5.4。仅有的运行时依赖：react、react-dom、jszip（打包导出）、pdfjs-dist（PDF 解析）。
无路由库 —— 自己用 hashchange 做路由；无状态管理库 —— 自己用 Context + ref 做 store。
存储：IndexedDB（原生 API，不用 idb 这类封装），外面套一层 `StorageAdapter` 抽象。
后端：一个极小的 Node 脚本做本机同源转发（默认只监听 127.0.0.1），用途见第 8 节。

3. 产品内核（四条铁律，任何一条动摇都算做错）
════════════════════════════════════════════
① AI 提议，人拍板。AI 永不直接改设定库，一切产出先进「审查队列」，采纳才入库，驳回即丢弃，也可先改再采纳。
② 执行档位只管「动作要不要先问」，管不到「产出要不要审」。即便调到最放手的档位，AI 新建的条目/关系照旧只提议。
③ 「AI 说没问题」和「我们没读懂 AI 的回复」是两件事。任何一处把后者显示成前者，都是 bug。
④ 静默失败（界面一切正常、内容没了）是最严重的缺陷类别，优先级高于任何功能新增。每一处失败都要在界面上有对应说法。

两条主线：
 ① 新建世界：投喂素材 → AI 读懂并追问 → 统筹成草案 → 你确认，世界才诞生。
 ② 日常协作：AI 产出候选 → 你审查拍板 → 才写入正式设定库。

5. 全局工程纪律（这 12 条是从真实故障里长出来的，必须实现，不是建议）
════════════════════════════════════════════
1) **写函数必须读库的最新快照**（一个 ref），不是点击那一刻的闭包。一次点击里连写两次同一条时，读旧快照会把刚存下的内容覆盖回去，且界面上毫无异常。
2) **做判断读队列本身，显示才读 React 快照**。连点三下时三下都发生在重渲染之前，拿快照判断会一律判成「没人排过」。
3) **AI 任务活在页面之外**（全局任务表），切页不中断，切回来结果仍在；结果必须显式存进全局任务槽。
4) **任务按世界隔离**：起跑时记下世界，读取时对不上就按「没跑过」渲染。
5) **AI 产出解析层要有「形状白名单」**（`LIST_KEYS`）。新增返回形状必须同步登记。**「读不懂」不许冒充「没问题」**：返回了能解析但没有列表的 JSON 必须报错，不许显示成「没有发现冲突」。
6) **深拷贝护栏**：传给「接受任意键」的参数（index signature / `Record<string, unknown>`）时要留意双变漏洞 —— 它会让类型检查形同虚设，别拿它当复制对象的安全网。
7) **转圈只表示「正在跑」，不表示「在等你」**。等作者拍板时不转圈，让按钮可点。尊重 `prefers-reduced-motion`。
8) **成功要说清做了什么、改了几条**，不是一个绿勾；失败要区分「做不到」与「还没做」，写成可执行的话（缺什么、去哪儿补）。
9) **删除必须连带**：删条目连带删掉挂在它上面的关系；删分类连带处理分类下的条目；撤销时**一并恢复**，只记主对象不如不给撤销。
10) **迁移要留痕且有闸门**：系统替作者改库必须写日志；迁移一次即可并用字段记下（否则每开一次越迁越乱）。
11) **依赖缺失要有明确指向**：没有世界 → 除设置外导航置灰并说明；没配 API Key → 指向设置页，不静默禁用按钮。
12) **DB 打开超时/被占用**要有引导（提示关闭所有标签页后重试）与「复制诊断日志」，且**数据不会因此丢失**。

6. 模块规格（15 个，按各自的边界实现）
════════════════════════════════════════════

【M1 新建世界】不提供「填表创建」，也不预置示例世界；第一个世界由人和 AI 一起长出来。
 四步：投喂素材（txt/md/docx/pdf/图片，本地解析，图片压缩后给模型读）→ AI 讲清「读懂了什么、来自哪份材料」再追问（每题附建议答案，可「你来定」/「换一批」，AI 判断收口，作者也可喊停）→ 统筹草案（世界名/定位/题材/创作纪律/底层规则/分类/首批条目含正文/关系）→ 确认生效。
 边界：确认前**不写任何世界数据**，一切在 drafts；作者单方面交代的话（told）优先级最高；条目同名在落库前拦截；素材一并进该世界资料库；纯文本模型读不了图时自动去图重试并如实告知；一个素材只纠一次错（避免来回烧 token）。进度自动保存、可中断续做。确认时再列出「AI 替你做过主的地方」。

【M2 世界总览】基本信息 + 创作纪律 + 条目/关系/杂物统计 + 结构体检（指出内容单薄的分类）。体检只指出问题，不自动补。统计口径与 Wiki、导出三处一致。

【M3 Wiki】一页三支，合并了「条目库」与「杂物间」，侧栏只留这一个入口；老地址 #entries/#pieces 仍落到对应子页（刷新后停在那儿）。
 · 阅读（默认）：左目录（按分类分组 + 搜索/状态/排序，**排序只决定组内先后**，三档都需名字兜底稳定排序）+ 右正文（本文目录、结构化字段、来源资料）+ 第三栏（双向关联、`[[内链]]` 可点跳转、支持「返回上一条」）。
 · 编辑：分类树/列表、别名、标签、自定义字段、关联条目 + wiki 编辑器（工具栏、`[[` 候选补全、语法高亮、快捷键、分栏预览、**编辑摘要记入日志**、草稿自动保存）。编辑器内一页「时间」。
 · 杂物间：长文/短文/碎片/描述/剧情 + 图片/音频/视频，碎片可速记、媒体可拖拽入库，可关联条目、可置顶。
 边界：搜索筛选**不把正在读的那篇挤走**；分类定义之外的旧字段不丢（label 用键名兜底）；封面只存引用；重开时摆「恢复/丢弃」草稿，**不自动套上去**；正文字段缺失照常入库并如实显示为空；删条目连带删关系、删分类连带删条目。

【M4 关系图谱】自绘力导向图。悬停弹信息卡、双击改名、右键改颜色/连线/删除、点两点建关系、点连线改类型与方向。
 边界：关系是**有向**的，方向写进句子里；半径按连接数**平方根**铺开（长尾下原始比例会把刻度吃光），深浅/名字浓淡按原始比例走；**压暗程度跟着眼前这张图的节点数走**，稀疏时不压；被隐藏的分类与关掉的待定关系**不算数**；待定关系可关掉不看；两端必须都存在。

【M5 时间轴与编年】与 M4 同一页、同一份数据。**核心：时间不是独立的表，它是条目上的可选字段。**
 · 时间（点轴）：一条轴 + 节点 + 标签分槽，右手边是「还没排进去」的条目池。拖到轴上任意处即落位，**位置就是它的时间**；也可点条目再点轴；**空轴本身当落点**。面板可改形态/起始/终结/纪元/分量/精确位置。
 · 编年：同一时间轴的四层读法（纪元带/卡片墙/甘特轨/刻度尺）共用同一套横坐标；卡片不重叠、顺序单调，挤成一撮的整组就地铺开并如实报数。
 · AI 自动排版：给一份先后方案 → 入任务队列 → **方案先落审查队列（采纳前轴上一点不动）** → 逐行勾选改数字 → 采纳时只写 `at`/`era`/`weight`。
 · AI 猜测时间：给还没设时间的条目凭空定时间（文本+位置）。**比排版更重**（它在替作者编日期），各自独立进审查。
 边界（九条，缺一不可）：
  ① 时间是两个字段：from/to 是作者写的纪年文本，at/toAt 是排序数值。只存文本会让「9 年」排到「10 年」后面。
  ② 形态三选一且**显式存**，不靠「终点空不空」去猜（作者填过终点又删掉，那份空白含义不明）。
  ③ 落位只写位置、不编时间文本；这类节点如实画成虚线圈。
  ④ AI 排版只写位置/纪元/分量，作者的时间文字一个字不碰。**唯一例外：锁定条目**（位置动了文本要跟着重写，否则锁定名存实亡）；非锁定条目绝不写文本。
  ⑤ 「至今」必须显式说。
  ⑥ 位置不由模型决定（它无从知道轴刻度）。
  ⑦ 「这次没提时间」≠「把时间去掉」：前者什么也不动，后者要明说 clearTime。
  ⑧ 两档轴距（按年代比例/均匀铺开）只是两种看法，不动数据。
  ⑨ 没有 toAt 的「一段」画虚线，不假装知道多久。
 降级：排版后位置没变的不列、排到一半被删的跳过、标题对不上的如实报数；**全部已排对时说「没有改动」**；对账要对两次（任务内比快照、落库前再比排队期间被改过的库）。

【M6 AI 工作台（内置 agent）】三档放手程度：计划模式（默认，读写都先摆计划等确认）/ 混合（读立刻、写等确认）/ 直接执行（读写都立刻）。工具共 31 个：
 读：world_overview / search_entries / read_entry / list_relations / list_timeline / list_pieces / list_docs / read_doc / list_review / list_ops
 写：create_entry / update_entry / polish_entries / delete_entry / create_relation / update_relation / delete_relation / create_category / update_category / delete_category / update_world / create_piece / update_piece / delete_piece / add_doc / delete_doc / update_settings / layout_timeline / guess_timeline
 其他：navigate / ask_author / note
 边界（14 条，全部要实现）：
  ① **agent 新建的条目/关系一律进审查队列**。注意铁律②的边界：三档档位只决定「动作要不要先问」，决定不了「产出要不要审」——别在最放手的档位上让写入绕过审查。
  ② 查不到就**停下来问**（带可点候选答案），不换关键词接着查；零命中 = 信息不够，该问不该查。
  ③ 只提到不存在的名字：先查、再问、**同时把能确定的骨架搭好送审**（提问与提议是一条链上的两件事）。
  ④ 补全类任务必须**先读正文再逐条比对**，人名器物多半只在正文里。
  ⑤ 清单没清空不许收工：想收工会被追问（最多两次），催不动就如实交出「还剩几条、是哪几条」；承诺了没动作要说破；清单挂会话上，切页刷新都在。
  ⑥ 不许说没核实过的话；**不许把「已提交审查」说成「已经建好了」**。
  ⑦ 记得上下文：系统提示词常驻「我们之前聊过」，**只带人话**，不带工具回灌与循环插话（否则它会把系统对它说的话当成自己讲过的）。
  ⑧ 同一动作实质只跑一次，但**只拦「成功过的那次」**（失败过的允许重试；写操作会作废之前的签名）。拦下时回执要引出上一次的真实结果。
  ⑨ 工具指认只用标题/别名，**不用内部 id**；参数名写歪了按别名折回规范名；两个参数名折成同一个键名这类歧义**不猜**，照实报缺。
  ⑩ 缺参数的报错必须能照着重写：说清缺哪个、该工具认哪些、你这次给的是什么。
  ⑪ 数据快照会过期：写操作后打脏标记，下一个动作前重取。
  ⑫ 视图操作不抢方向盘：agent 建议去某页 → 渲染成可点按钮，不在你读回复时把页面拽走。
  ⑬ 多步循环有限度：**最多来回 20 轮**，超出停下说明情况。
  ⑭ **ask_author 是终结性的**：执行到它这一轮就结束，后面动作一律标「跳过」，不拿假设当事实；它也不受三档边界约束（要作者先批准它提一个问题，本身就很荒谬）。
 协议修复：模型几乎必然写歪 JSON（对象当数组、键名换掉、plan 被序列化成字符串、两个并列 JSON、根级直接给动作、动作对象少写收尾括号）。按「**只要表达了动作就必须救回来**」实现，逐 token 结构修复排在「有损切尾」**之前**（次序搞反会把 8 个动作静默切成 1 个还报成功）。修复要克制：改动次数超阈值就放弃并报「没按协议」。**修好了也必须说**（repaired / retried / gaveUp 三种分开标注）。零结果也要分开报：empty（该去问作者）/ badCall（该照参数名重写）。

【M7 审查队列】所有 AI 提议的唯一收费站。逐条 diff 预览 → 采纳/改一改再采纳/驳回；按类型与状态筛选；同批（`batchId`）自动归组可「采纳这一批」；带来源徽标与理由；支持**再一次生成**（重跑原任务、可附加提示词、替换旧提议并可从 superseded 撤回）。
 边界：两端未落地的关系提议在采纳前**拦下**（应用层与 store 各一道守卫）；**同一目标不许叠两份待审修订**；提议也是写入、同样可撤销；撤回提议时依赖它的关系提议一并收回；采纳条目时挂在它上面的关系跟着落地；「再一次生成」记可复现的输入而非整份快照；一次排版/猜测是**一整条提议**，不拆成 N 条「修改条目」（拆开就丢了「这几条之间的先后」）。

【M8 资料库】上传 txt/md/json/csv/tsv/html/yml/docx/pdf，或在线输入/粘贴（页内 Ctrl+V 即存）；AI 读完拆成结构化条目送审。资料是**只读存档**，抽取结果是提议，不覆盖已有条目。解析不出文本（扫描件/加密）如实标注，可手动补文本。新建世界投喂的素材自动进来。条目上的 sourceRefs 指回它。

【M9 一致性检查】扫描全部条目（含各种参数）+ 相关关系，找出矛盾并给改法。**核心是带账本审计**，每轮带账出去，分三组：
 「仍未处理」→ 不重复报（本来就在页面上挂着）；「作者已判定且相关条目此后没动过」→ 不重复报；「可重看」→ 已判定但相关条目在那次判定之后又被改过，允许重报，**条件是必须写明相比上次的变化**。
 边界：**可重看靠时间戳判断（`entry.updatedAt > issue.createdAt`），不靠模型**（让模型比时间戳它只会瞎猜）；
 **入库前还有一道兜底**：解析层拦下库里已经说过的，并**如实报出拦了哪几条，不闷掉**；
 **判重刻意保守**：只认字面级重复（归一后相同，或一个套着另一个），不追「换个说法」（同一条问题的两种说法相似度可能低于两条不相干的问题）—— **宁可漏，不可错杀**；
 **送入范围要说实话**：索引条数跟着 contextLimit 走，正文有**总预算**并按条目数平分（只有单条上限而无总量上限时，服务端会悄悄截尾，而排序在前的那批每轮都排在前，于是模型每轮只看到同一批，报出来的永远是那几个）；横幅如实写出「最多列几条、每条约多少字」；
 **全部生成修订按涉及条目分组**，同一条目上叠着三条冲突不要连着改三遍（后一次会推翻前一次），合并后每条修订只占队列一个位置；已有待审修订的条目这次先放过并提前说明跳过了几条。
 降级：四种结果分开报——生成了几条、几条被并进同一条修订、几条生成不了（相关条目找不到）、几条失手（可单独重试）。合成一句「已完成」等于什么都没说。

【M10 问答存档】只读历史页：回看过去的对话，以及每条回答引用了哪些条目。追问能力已统一到 M6。引用失效如实显示。

【M11 操作日志】每一次写入都留痕：谁（user/agent）、做了什么（create/update/delete/note/view/propose）、改了哪个字段；每条带撤销快照可逐步回退；按来源与实体类型筛选。
 边界：只存结构化事实，**面向人的措辞不落库**（否则切语言后历史卡在旧语言上）；undo 是 remove+restore+settings 的**集合**；纯留痕（note）不改数据且不可撤销；撤销顺序倒着走；撤销目标已被二次修改时如实说明或拒绝，不静默覆盖。

【M12 文章审校】粘贴章节/片段 → 检索相关设定 → 报出冲突与推荐补充的新条目。只报与既有设定冲突的地方，不做文笔批改、不做事实核查；推荐的「新条目」是建议不是自动创建；temperature 走低区间（这类任务要严谨：0.2–0.4，设定创作才是 0.7–1.0）。**零命中时不说「没有冲突」，要说「库里没有相关设定，无法判断」**。

【M13 导出设定集】一键导出 Markdown / HTML；`[[内链]]`、目录、关联、大事记引用折成**真能跳**的可点击链接（导出稿里不该出现裸露的 `[[ ]]`）；HTML 版内联表格/图片/音视频；支持 JSON 备份与恢复。
 边界：**设过时间的条目汇总成「大事记」一章**，按时间排开，纪元换段处开小节，**刻意不按纪元重新分组**（为了凑整齐而重排会把历史顺序讲乱）；大事记这章可在导出选项里关掉；JSON 备份必须完整可恢复（含杂物媒体 Blob）。

【M14 任务队列】右下角胶囊。AI 一次只做一件，连点几下排几件，**严格串行**（并发会撞上游限流、且写库顺序会乱，而作者的点击顺序本身就是意图表达）。展示正在做什么/还压着几件/失败原因；展开可撤单/重试/清空已完成；切页不丢。
 边界：**同一条条目上只许排一件**（两个活儿同时改一个条目，作者会不知道按哪份改），被挡下要明说并指向批量入口；**做判断读队列本身**；**撤单是真的省钱**（排队中的那件一个请求都不会发出去）；**通用设施、不认识业务**：队列只知道「有一件活儿要跑」，名字由发起方给，新增接入点只需一次入队调用并带上 navKey；活儿带 navKey 排队，与页面内 AI 任务在侧栏取并集（那一格转圈是「哪一页在干活」唯一能一眼看到的地方）。

【M15 设置】
 · AI 模型：**20 个厂商预设**，分三组展示（常用 main / 聚合与海外 aggregator / 本机 local），全走 OpenAI 兼容协议。型号：内置型号只是兜底；点「选型号」去厂商 `GET /models` 拉**这把钥匙真正能用**的清单并缓存本机，只有点「重新获取」才再拉；可搜索；按「能对话的在前」排，**非对话模型标一句「可能不是对话模型」挪到后面而不是藏起来**；拉失败要摆厂商原话且**不丢上一份好清单**；**型号永远可以手填**。
 · 可用性探测：清单到手自动逐个探（一个 max_tokens:1 的极短请求），四态 —— 绿（真的回话了，**2xx 但内容为空不算**）/ 橙（余额或额度不足，单独一档，该做的事是充钱不是换型号）/ 红（型号有问题）/ 灰（还没探过，**「没探完」不等于「不可用」**）。悬停带厂商原话。**向量/语音那类根本不探**；结论缓存 24 小时且跟着 API Key 走；连着几个连不上就收手；跑的过程中可停止；选中未探测型号时单独探一次；**入口只有选型号面板里那一处**；探测上限可调（默认 40，最小 1），可勾「不限制」，没探到的如实报「还有 N 个没探」。探测不污染对话计数。
 · 切服务商：每家各记一个型号；被改成中转站的地址也一起记着，旁边有「恢复官方地址」。
 · 采样参数：temperature（创作 0.7–1.0 / 检查与审校 0.2–0.4）、max_tokens（0=不限制）、top_p（1.00=不传）。
 · 流式接收：默认开；网关流式不老实时才建议关；关掉后仍要补一次回调。
 · 高级选项（默认收起）：JSON 模式三态（auto/always/never）；额外请求头（JSON 对象，**同名字段不分大小写覆盖内置 Authorization，直连与本机转发两条路都带上**）；额外请求体（与内置合并，`messages` 不许覆盖）。**两者都存文本不存对象**（作者正在敲一半时那不是合法 JSON）；写歪了就地报红、发送前拦下、不静默忽略。
 · 读图：图片压缩后交模型；读不了图时自动去图重试并如实告知；可整体关闭。
 · 界面语言：简中 / English / 跟随系统。即时生效并持久化（偏好写 localStorage），`<html lang>` 与标题同步。**AI 提示词也跟随语言**（英文界面就发英文提示词），**agent 的角色设定、工具说明、执行回执也是语言包的一部分**。
 · 世界管理 / JSON 导入导出 / 清空数据（**清空不可逆，二次确认**）。

════════════════════════════════════════════
7. 不需要 AI 的底层能力（先做这些，M1–M15 都依赖它们）
════════════════════════════════════════════
· **检索打分**（BM25-lite）：标题命中 +6、标签 +4、摘要 +3、正文 +1；定稿条目 ×1.15（更权威）。另有余弦相似度，**仅用于近重复判断**。
· **diff**：字段级 {field, before, after}，供审查队列与日志用。
· **导出渲染**：Markdown → HTML 的渲染；**行内代码里的 `[[ ]]` 不解析**；不要把英文排版那套「在行内代码与文字之间补空格」照搬到中文上，中文里会很难看。
· **文件解析**：各格式的本地抽取（PDF 走 pdfjs-dist），失败给出**具体原因**。
· **图片压缩**：压缩后再交给模型；压缩后要**修正宽高比**。
· **诊断日志**：DB 打开每一步、本源下所有数据库的名字与版本，可一键复制。

════════════════════════════════════════════
8. AI 接入层
════════════════════════════════════════════
· 请求：走 OpenAI 兼容的 `/chat/completions`；SSE 流式接收为主。
· **跨域兜底**：直连失败自动改走本机同源转发（`/__wf-proxy`，只监听 127.0.0.1）。转发器**原样转发**额外请求头（只滤掉 Origin/Referer/Sec-* 与逐跳头）—— **不要重建请求头**：早先它把请求头重建成固定的几个，于是同一个配置直连能用、一退回转发就悄悄没了，而厂商只回一句「参数不对」，极难查。
· **模型不认识的写法处理**：JSON 模式做成三态（`response_format`），`always` 会对不支持的网关 400，`never` 反过来在有些自建网关上吐不利索，`auto` 按任务需要决定。
· 采样参数跟随场景：设定创作 0.7–1.0；一致性检查与审校 0.2–0.4。

## 使用建议

1. **先给 P0 再给全局**：如果你的新 AI 上下文有限，可以先只发「第 0–5 节 + P0」，等骨架稳了再补后面。
2. **把源码作为参考一并附上**（推荐）：这份提示词定义的是「做成什么样」，源码定义的是「具体怎么写」。两者一起交，还原度会高一个数量级。建议附上 `src/types.ts`、`src/ai/parse.ts`、`src/ai/agent/protocol.ts`、`src/state/store.tsx` 这几个约束密度最高的文件。
3. **不要指望一次性生成**：约 4.8 万行的量级，按 9 个里程碑推进是现实的节奏。
4. **重点盯验的几处**（这些是最容易做错、而且错了之后表面看不出来的地方）：
   - 「读不懂」被显示成「没问题」
   - AI 是否真的只提议不落库（试着把执行档位调到最放手的那档验证）
